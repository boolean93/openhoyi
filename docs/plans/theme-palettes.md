# 应用主题配色

- 需求与范围：外观与语言保留独立的深色主题开关，新增经典绿、海盐蓝、咖啡棕、石墨灰。色板可以先预览后应用，取消不写入；成功后同一 App 内的导航、主按钮、选中态、应用开关及装饰一致换色。经典绿兼容已有的产品、旧页面和首页绿色变体；原生控件的系统强调色跟随配色。不新增背景图、导入/文件权限或联机功能。
- 来源分支/基线提交：`develop` + `3d51c03723ae207f3ae632a7ab3ec85cf5ce621c`。
- 工作分支：`feature/theme-palettes`。
- PR目标：`develop`。
- 改动文件与步骤：共享外观存储及 Activity/预览上下文、品牌颜色角色与原生样式、Fragment/旧 Activity 共用设置组件，迁移使用品牌角色的视图；单独固定此前借用品牌色的曲线指标。保留既有 `appearance.dark`，新 `appearance.palette` 缺失或未知时回退经典绿。
- 推送与合并：仅普通推送工作分支，并从 `./scripts/create-pr` 创建 PR；同一 PR 头提交的 `branch-policy` 与 `verify` 通过后才合入。合入后 develop 设备工作流不代替硬件验收。
- 验证：测试旧偏好、未知键、深浅与色板独立、失败/取消不换色；Mock 界面夹具检查实际色卡入口、预览和重建，以及字号/窗口代表场景。确认曲线语义色、告警红与停止色固定。核对主题重建沿用已有编辑器/AI 草稿和前台服务生命周期，无本地 AVD 或真实设备操作。
- 协议与设备风险：纯应用外观，无编码、单位、队列、重试、启停、连接或未知记录更改。不以 Mock 证明硬件行为。
- 发布：不人工发布、不打标签、不改变版本、签名或升级边界、不安装。
- 回退：使用 revert PR；旧版继续读取 `appearance.dark`，忽略新增的 `palette`；不删除偏好、草稿或历史，不卸载。
- 未完成与阻塞：背景图及其可读性、导入和持久化属于后续单独 PR。

Mock 设备用例仅在隔离的 CI 模拟器运行（不新增常规 PR 门槛）：

```sh
gh workflow run mock-lifecycle.yml --ref feature/theme-palettes -f theme_palette_checks=true
```

它使用合成的萃取和输入验证重建，不发送 BLE 或模型请求。检查四套色板在深浅模式下真实绘制的开、关、禁用状态，上传浅色海盐蓝和深色石墨灰示例窗口、精确源码及 Mock 包身份凭据。测试通过不代表真实设备验收。

具体规则以 [Git工作流](../git-workflow.md) 为准。
