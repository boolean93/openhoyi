# Private same-package Android BLE V2 acceptance harness

`-PhoyiBleSameIdQa=true -PhoyiBleV2Delivery=true` enables the single Mock-only diagnostics row; the normal Mock, Debug, and Release do not compile the visible fixture. The core port is guarded by the separate BuildConfig flag, and ordinary Mock need not enable the V2 delivery gate. The row has no manifest entry, receiver, permission, launcher or network changes. Nothing runs automatically. This slice defines one bounded exercise for all 21 supported intents, 13 guard format/descriptor denial probes, plus active-sync, full synthetic authorized rebind readback, and disposed-owner checks. Tests inject synthetic events into a real detached MobileService and a recording fake. No Android process-death, downgrade or real transport is tested by this CTA; building does not run it and those omissions remain explicit.

## Detached factory and remaining scope

The entry uses the explicit `withDetachedCore` factory on main with a bounded synthetic clock and releases each case before the next. The CTA schedules only one case per main-loop turn, locks the button against duplicate execution, and stops if the visible host detaches. No reflection, framework Service lifecycle, real Application/curve-store/telemetry sharing, system service, permission lookup, real driver fallback, unscoped filesystem, user data/history/keys, nor writes outside optional dedicated QA files. Inject the driver at creation, through the real guarded native hub/session path. The optional curve domain reads only packaged immutable factory assets and verified wire reference tables; optional shot effects use empty in-memory bean preparation, isolated in-memory history/timing/sample counts, and no provider/network or feedback audio. All device operations must be synthetic. The diagnostic screen stays ordinary Mock; separate diagnostic output is runtime service evidence, not evidence that a normal settings click uses that same path.

Return a report with the expected matrix counts and all outcomes, separate requested/queued/submitted/GATT complete/evidence-confirmed records, one same-case test of changed/missing readback, stale or wrong generation, schedule P1/P2 verification, STOP priority, no replay. Record actual submitted fake writes and positive/blocked cases plus zero real transport calls. Keep controller entirely test-owned and no raw frame payloads, passwords, hardware addresses or history in UI/report. A missing test row, reached fallback, exception or false confirmation means failure, not passed or skipped. Main thread capture should run bounded deterministic batches rather than wait/sleep for physical side effects.

## Durable C3 integration and remaining lifecycle coverage

The combined harness now invokes the shared actual C3 canonical broker initialization and clock, after pinning only a uniquely created QA no-backup root. The overlap case requires the two weekly writes to complete before admitting one boiler write, then independently records the boiler settings and weekly pair. A second case closes the original detached owner with two UNKNOWN entries, reopens a new service and driver on the same isolated on-disk marker, and independently explicitly resolves each entry without issuing control writes. This is a persisted service recreation, not actual Android process death or proof of device-selection admission: the synthetic port boots the known fixture address directly through the fake native hub. A fail-closed lease retains the synthetic cache without reuse if driver, pin or trace retirement cannot be proven. A marker read/sync error or app-version rollback needs separate coverage. Ordinary Mock uses neither split flags nor the fixture storage.

Further lifecycle checks beyond the combined CTA:

1. Marker saved but gate prevents fake dispatch: after rebuild no replay; clear/retain marker only if the actual durable state proves it was not handed off. Inject write or fsync denial and expect zero real and fake control writes without a valid committed marker.
2. Handoff succeeded then callback missing or interrupted: rebuild -> UNKNOWN, no automatic command retry; synthetic stale same-address frame or different device cannot clear. For weekly, crash between fragments and verify P2 is never resumed.
3. Fresh same-device valid observation can reconcile when its command evidence permits. Crash at the clear boundary and inject clear failure: next owner retains actionable marker, cannot claim success for a stale owner. Any legacy/shared fence must remain closed if read fails, prior file is corrupt, or version/schema is unsupported.
4. After explicit reapply or review, only the newly issued, permitted intent can send; tally fake writes and verify old owner has no callback authority. Report service recreation with file persistence, not process death unless independently forced and measured on an approved disposable Android runtime. A real app rollback test needs the actual prior reader, no fictitious versionCode bump or device downgrade without authorization.

Each panel owns a single detached V2 service with a fake driver, from opening until dismissal or view detachment. They exercise product readout rules rather than stock Mock mutations; the schedule navigation is preview-local and is not a test of actual MainActivity tabs.

Then deliver the weekly pair; P1 alone stays pending, P2 confirms.
