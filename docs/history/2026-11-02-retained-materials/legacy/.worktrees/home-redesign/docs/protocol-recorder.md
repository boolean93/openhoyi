# 当前改版的操作与蓝牙记录器

## 基线与用途

基于可用改版 `ebd202e`，不改咖啡机/秤协议编码或连接业务。记录默认开启，完全离线。每次进程启动建立 session；同一 session 内有递增 seq、墙钟时间、相对时间、用户动作 ID、BLE 操作 ID、手动场景名。

`session.start` 保存基线、构建时 Git revision/dirty、不含记录器的业务 bundle SHA256、记录器源码 SHA256、production/mock 标记。`recorder.environment` 保存系统版本和设备型号；每次 BLE 记录附当时已知的咖啡机/秤身份、固件、连接状态、压力、温度、重量。初次连接前未知字段允许缺省，不能将其当成版本已确认。

## 使用

1. 安装本次生成的 `HOYI alpha`（真实设备）或 `HOYI Mock`（UI）。
2. 顶部中央显示小型“● 记录中”入口。首次存储初始化之前或日志发生丢失/写入异常时显示“记录异常”。
3. 正式操作前点击入口 → **标记本次操作场景**，填写例如 `BOOKOO / 曲线库 / 压力两段 / 36g / 自动停止`。
4. 正常使用 App。选择曲线、确认配置、开关、按钮和输入事件通过实际渲染监听器记录；自定义组件事件也记录，可能与子组件点击形成嵌套动作。
5. 点击入口 → **导出当前/历史日志**，选择文件，通过 Android 系统分享面板保存或传给自己。导出的是独立快照，后续采集不会改动已分享文件。记录器本身不自动上传任何内容。
6. 可以暂停/恢复；暂停会留明确事件，暂停区间不能作为完整回放样本。

浮层菜单另有“导出旧版萃取历史 JSON”，读取当前安装包私有存储的 `brew_history_v1`，通过同一系统分享面板保存完整 JSON，供 OpenHOYI 原生版历史页显式导入。它与协议日志导出相互独立；没有历史或数据格式不符时会拒绝导出。不同包名的原始版私有数据不会自动转入本修改包。

同一菜单的“导出已保存曲线库 JSON”保存 `hy_chartLib` 全部数组、工厂曲线版本和分类配置；未保存到该存储键的编辑不会进入导出文件。原生版曲线库只读导入。它不会将导出数据上传，也不触发咖啡机命令；原生版在逐条报文对照前不能用这些曲线萃取。

文件保存在 `_doc/protocol-recordings/<session>-<part>.jsonl`。每约 16 MiB 轮换文件，同一 session 的所有 part 应一起收集。保留历史文件，不自动删除；导出快照在其 `exports` 子目录。请定期导出，空间不足时会显示异常。已覆盖安装并确认日志落盘（首批 42 条，格式与序号检查通过）；设备停在锁屏，系统分享和 DCloud native View 的实际显示仍待验证。

## 记录边界

- `ui.before/ui.after`：页面/组件、节点 `_i`、事件、当前曲线和配置前后快照。模板的内联修改和自定义 release/change 事件也在范围内。
- `dialog.request/dialog.result`：原生 uni 确认弹窗的标题与确认/取消结果，后续同步写入关联到该弹窗动作；不保存输入框内容。
- `ble.request`：实际调用的 API、设备、服务、特征、原始 ArrayBuffer 的 hex、长度、opcode。不是“准备构造的包”。
- `ble.result`：success/fail/complete 或 Promise resolved/rejected，与 request 共享 operationId。GATT success **不代表**机器已经执行。
- `ble.notification/ble.event`：收到的原始通知、连接变化、扫描结果。记录的是 listener delivery，同一系统通知给多个 listener 时可能重复，不能用行数推断设备发送频率。
- BLE 与 UI 同步调用共享 actionId。延时或异步发生的请求保留 lastActionId 作为参考，但不声称它是因果关系；应结合场景、时间和状态复核。
- 记录由 Vue 事件监听器驱动，后台定时器和原生弹窗回调不能冒充用户点击。它们产生的 BLE 通信仍然全量记录。静态事件清单用于逐页核对，不能仅凭“已注入”声明所有交互已验证。
- 协议 `0x01` 的六位密码和 XOR、`0x0B` 的密码尾部以 `XX` 替换。密码组件的通用 value 及原始输入 detail 不记录。脱敏帧不能直接作为逐字节回放 fixture。
- 曲线/配置结构有深度 5、数组 128 项、字符串 4096 字符上限。BLE hex 不裁剪；丢失时丢整条并标明 gap。

每秒异步写一批，单批最多 128 条，待写队列最多 2048 条。写失败保留批次重试并累计错误；恢复后写入 `recorder.storage_error`。队列溢出累计 dropped 并写 `recorder.gap`。进程强杀/掉电可能丢最后的内存尾部，这一部分无法由进程自身保证。没有观察到 gap 也不等于完整；导出前会尝试排空队列，失败则提示，不输出“成功”。

## 覆盖与分析

```bash
python3 scripts/recording_report.py captures/*.jsonl --output coverage.json
```

报告去重 `(session, seq)`，检查 JSON 损坏、序列缺口、暂停、存储错误；按命令格式区分启动/停止和复用 opcode；列出场景、UI 节点、通知和回调结果。存在缺口/错误时退出码为 2。

报告的 `observed` 只代表在边界看到发送请求。`replayVerified`、`hardwareVerified` 默认始终为 false，后续需要独立证据才能提升。不能把 ACK、按钮点击或运行次数当成硬件兼容性证明。

[静态事件清单](recorder-event-inventory.json) 从编译模板生成，包含 252 个事件绑定位置、所属 bundle 模块、原始绑定表达式和候选 handler。它覆盖业务与公共组件，因此不等于 252 个产品功能。对应命令清单在 `scripts/recording_report.py`；以下矩阵是第一轮实际采集清单。

## 开发与验证

- `recorder/runtime.js` 为维护源；`scripts/sync_recorder.py` 将它和版本指纹嵌入业务 bundle 头部。
- 唯一额外业务插入点是在构建 App 实例前注册 Vue 观察 mixin。不要手工改注入块。
- 构建自动同步；Mock 的 transport 先注入，记录器再包住它，因此 Mock 日志必须作为模拟样本。
- `python3 scripts/recorder_inventory.py` 更新静态清单。
- `node --test tests/protocol_recorder.test.cjs` 验证透明调用、事件快照、脱敏、失败和写入。
- `python3 -m unittest tests/test_recording_report.py` 验证报告不会把重复/不完整数据误当覆盖。

第一批只需一次正常连接、一次完整萃取、一次正常温度设置。拿到这些真实日志后再确认字段、时序和记录完整性，随后扩展其余场景。
