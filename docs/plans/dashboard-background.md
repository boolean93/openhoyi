# 修正首页照片被整块底板遮挡

- 需求与范围：按用户截图修复首页。保留圆形表盘自身底面，让照片在圆盘外、两列之间和分组之间贯通。压力及锅炉开关每列共用一个小圆角底，快捷标题及图例单独共用一条窄底。已有底面的模式按钮、短窗锅炉卡及曲线卡不改布局。
- 来源分支/基线：`develop` `95b11163`。工作分支：`fix/dashboard-background`。PR 目标：`develop`。
- 实现：只在首页标记新增圆角保护区域；未设置背景时，不变更控件、颜色、排版、触控和事件。测试修正旧的“两表共用整块矩形”验收。
- 推送与合并：本地相关验证及 `./scripts/create-pr` 门禁后正常推送；同一提交的 `branch-policy`、`verify` 通过，另取隔离云端 Mock 首页浅深实际窗口证据，独审后合入。
- 验证：同一 APK 用纯色及高反差合成照片核对默认底、圆盘实底、各小面板和透图空隙。私有用户截图不进入仓库或 CI；不运行本机 AVD。
- 协议与设备：不修改机器控制、连接、写入、停止、预热或历史，不连真实设备。
- 发布与回退：本 PR 不打标签、不发正式版；混淆 Mock 由协调线程在核验源码、签名、版本和升级边界后交付。必要时回退此代码，不清背景偏好、照片或业务数据。
- 验证进度：本地 Mock 仪器测试代码定向编译及首页布局、背景单测通过；云端实际窗口待验证。

具体规则以 [Git工作流](../git-workflow.md) 为准。

## 逐页举一反三

| 实际窗口 | 可读性保护和背景断言 |
| --- | --- |
| 首页，浅深 | 圆盘及模式用自己的底；模式禁用保留原有整控件不透明度 45%（不视作实底），深色忙纹另取真实窗。压力和开关各一组，标题和图例独立；验证圆外、两列间透图以及恢复纯色的控件位置。 |
| 曲库，浅深手机＋短横窗 | 搜索、筛选、计数和状态提示统一工具组，与结果列表分开：透明行使用圆角列表窗口，原有曲线计划卡保留；看列表角落及工具/列表间隔，另取一张深色实际详情。 |
| 设置，浅深手机＋短横窗 | 页头与各设置节圆角，滚动后按原始边界裁切，节间空白透图。 |
| 电子秤，浅深手机＋短横窗 | 重量、去皮说明、计时、设备和趋势分别有业务内实底；读数角落透图。 |
| 历史和咖啡豆，浅深 | 数量与工具成组、空态卡自有圆角，非空列表有独立窗口。不添加或修改业务记录。 |
| AI，浅深 | 验证欢迎、非空气泡与推荐卡、顶栏渐隐，保留键盘和附件菜单的独立验证；不发模型请求。 |
| 萃取，浅深 | 只看准备页支持信息与原有实底图表，验证外侧留图；检查未启动、未预热。 |

只显式标记核对过的容器，不根据所有 GradientDrawable/RippleDrawable 猜测实底。带选中态的列表仅启用照片时裁切圆角，恢复纯色后复原原始 outline。复用背景验收工作流，仅为新增页面补代表截图。取证时，原图探针须与所有可接受的实底色每色至少一个通道相差 5，宽于真实窗口匹配容差 2，避免近底色误过。双列中缝在原间隙内使用局部平坦的裸图点，避开位图硬边的软件/窗口插值差。失败只采集对应白名单的最后一帧，并记录实测点，不计入通过。仅像素取证失败可继续独立页面，最后汇总为失败；状态、配置和布局前置错误仍立即终止。
