## 体验反馈后的保护修正

用户在旧会话继续“给卡片”时，回复仍称跟随按关闭填写并让用户事后核对首段时间。本图证明回答错误，不足以证明当次请求/安装来源、工具 JSON 或是否触发压缩；不能把先前预置正确 JSON 的假模型测试当作识图验收。

代码核查：IMAGE 直接经 AiAttachmentConversation.wire 进入同一聊天模型，不经过文档 OCR；AiProtocolTurn 每轮注入当前 system，但原样回放旧 assistant/tool。之前完整 HOYI 规则只在 proposal 参数描述，旧错误没有明确的证据优先级约束。现在完整指导只保留在 system 一处，明确旧答复、旧卡片/提案、摘要不是原图证据；无法重核的必填项先问，不得先成卡再让用户核对。压缩摘要保留字段单位、原图与助手推断来源及冲突，不能默填 false/0。

新增实际请求构建回归携带原图 manifest、旧错误 false 提案及旧答复，检查当前 system 与原图进入最终 wire；这是出站内容测试，不证明真实模型服从或 OCR 正确。没有调用付费 API、读取用户会话私有数据或操作设备。

### 结构化转录与原生绑定（纳入本轮）

新增现有附件菜单中的“HOYI 曲线截图”，复用图片选择、压缩和发送同意，不自动上传。普通图片/豆袋图片不启用此模式。原生选择绑定当前图片，持续显示模式提示，可从＋菜单明确退出；生成草稿不自动退出，避免下一轮修正绕回通用提案。绑定加入加密 AiSession schema6 并在该会话内恢复，旧schema1–5没有绑定；来源缺失、非图片、元数据冲突或无法读取时拒绝，不静默退回普通创建。跨模型会话各自保留绑定，不从其他会话借ID。原图仍可能被历史引用，退出模式不删除文件。

沿用 propose_custom_curve 工具，显式导入模式只接受 operation=transcribe_screenshot，拒绝 create、replace、copy_from_factory 旁路。转录提供原界面模式/逻辑标签枚举与展示单位数值，不能提供派生flags。AiHoyiScreenshotProposal 本地确定性映射：follow=true，constant=false，hs=true/ls=false，首段10s→firstDurationSeconds，闷蒸5s→preinfusionSeconds；倍率由代码完成。全部字段必需，null/未知/不相容模式或单位/精度不支持均拒绝成卡；不补默认、不夹限。普通非导入模式仍保留原有新建、编辑、工厂复制。原生卡确认只打开编辑器，仍需用户显式保存。

可信来源ID只能由原生选图设置，不接受模型自报sourceKind建立模式；每轮追问重新附上绑定原图，并按现有图片/请求/上下文预算计费与限制。schema6往返、旧版兼容、外来ID、非图片、元数据冲突和跨模型隔离均加入离线测试。该实现能阻止“已转录follow却写false”的字段映射错误，仍不能保证模型正确识读原图标签。没有真实模型/实机识图验收，不作相反声明。旧失败会话须从新专用入口重新选原图，不能仅回复“给卡片”建立可信导入模式。
