# BLE 应用层 v2：回报来源与操作证据（未接入准入）

- 来源：`develop` 2496d5dc，阶段三本地 00a7c4f5；工作分支 `fix/ble-v2-frame-provenance`；若另获批准，PR 目标 `develop`。无推送、PR、发布、设备或本地模拟器。
- NativeDeviceHub 只读 sidecar 暴露 DeviceSession 实际入口识别的证据。在现有代次、通知端点、解码与 READY/认证之后，记录来自本连接的实际到达顺序和单调时间，原回调签名、顺序、状态与命令路径保持不变。初始认证/同步缓存的回放不是操作证据。新连接即使代次编号和设备地址相同也不复用 opaque source。
- 锅炉：严格使用设置分型 0x83/<0x40；需要同连接、发前观察仍对应游标、所选开关原值异于请求目标、成功传输后的界线、最新且新鲜的目标位确实匹配请求。另一个锅炉或日程回报不能确认该请求。任何回报证据都不是固件事务 ID，不能排除其他控制端或机器自身修改。
- 计划：严格使用 0x83/0x40 和 0x83/0x80 两段，第二条写入成功后的界线之后、同连接按到达顺序完整匹配整周；先来的后半段不用，新前半段替换等待中的前半段，并沿用已有两段最大间隔策略。无需根据猜测发一条同步写入，也不移除当前只准串行的规则。
- 此处 sidecar 最多保存最新一帧。后续串联消费需要在同一线程用它的原始 envelope，不能把缓存最新一帧硬套在旧回调上。尚未实现把该证据写入新恢复账本，也未实现持久操作具体目标、指令等待总时限的上线政策、重启后确认或同时控制。STOP、GATT、恢复协议和权限均不变。
- 验证：使用真实 DeviceSession、假 GATT 驱动和协议报文测试两个写路径、早于回调/错棒/错设备或代次、日程残缺/乱序/错目标。仅离线，回退代码不涉及数据迁移或清理。
