# 历史保留中断前机器计时

- 需求：若一杯经历结果未知或连接中断，迟到待机可确认停水，但不能把中断前的最后机器整数秒当完整时长。历史、对比、导出与只读 AI 数据一致区分；采样覆盖仍为首末有效采样间隔，可能含缺口。
- 基线：`origin/develop` @ `98c392a1`；`fix/history-interrupted-timer` → `develop`。
- 方案：沿用控制器按杯粘性证据；只冻结本杯机器计时（包括空值），不停止采样。用同杯原子写入更新历史状态与计时证据，按 ID 同步 Journal，不覆盖用户笔记。历史主文档仍最多 13 列，Journal 主文档仍 schema 3。独立校验的 app 私有 sidecar 按 ID、曲线与开始时间保存证据，不从旧记录猜测或恢复已删记录。历史主文档与 sidecar 在同一 SharedPreferences 提交，Journal 和只读 AI 仅合并证据；显式导出可以使用扩展格式。
- 验证：JVM 验证迟到待机、冻结空值、正常杯、旧格式、重放/写失败及导出。按 [Git 工作流](../git-workflow.md) 运行完整 PR 检查、独立复核，通过 branch-policy 和 verify 后合入。无真机操作或本地 AVD。
- 协议和发布：不改协议、设备启停、重试或安全状态；不人工发版、不改签名或版本。内部写入兼容旧版历史和 Journal；旧版可保留历史、采样与笔记，但不认识中断证据，主记录不向它提供可能误读的中断秒数。向后往返只在隔离夹具验证，不降级用户设备、不清历史和未确认记录。
