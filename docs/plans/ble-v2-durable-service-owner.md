# BLE V2 持久所有权 A：独占服务 writer

- 来源本地 e60f44c4，目标后续 develop。仅本地验证；不推送、不打包、不安装。默认普通配置沿用原算法；显式 V2 实机 Debug 编译模式才挂接。
- 实际 MobileService 在 onCreate 最早先固定规范目录和 marker 的进程级 writer，再读旧记录和初始化连接；与 Stage3 split 写方、历史逐次写方共享同一 canonical marker 锁，观察方不持久占用。没有实际 writer（争用或异常）返回 UNKNOWN 围栏，不启动新 Hub／认证或普通控制，不把未知写成空；持锁但旧记录 UNKNOWN 仍按原安全读回规则。
- A 保持原持久格式和解决策略。持锁读取原文件／镜像，旧格式才允许写；拆分围栏、未知字段、损坏内容不得改写。关旧 Hub 先拒绝新的普通调度，已有 GATT/回调在持锁期间收束；真实关闭异常时，本服务不能复用也不能由新服务抢开 Hub，直到进程重启不释放锁。STOP 继续直接走同一 GATT 紧急路径，不需要本层存储许可。
- A 不允许并行写，不启用 split marker，不属于运行验收。后续 B：同一 backend 兼容 typed owner/内容/CAS，重启只恢复观察，旧读者关闭失败；C：逐项矩阵显式冲突许可，首个只允许已发送完的 09 待回读和一个安全独立锅炉目标，仍禁止对周表打断性同步重连。
- 回退 A 不需迁移或删除数据，原历史 marker 和状态保留。末端挂接不等于真实 Android、旧 APK 原地回退或实体机器验证。

## B：按意图持久化与恢复 CAS（尚未接入操作准入）

- 版本 2 扩展保存精确目标：冲泡／蒸汽与开关值，或完整周表七天（含启用和时分）。原来的 v1 记录仍可读，未知目标不能假装可确认；不能混写两种版本。朝旧读者保留 UNKNOWN 顶层和空地址，不授予旧客户端控制。
- 读取待处理记录只签发专用恢复令牌；此服务实例直到退出都不能用它发任何操作，哪怕最后一项已人工清除。兼容判断必须用持久化的确切原始 bytes CAS，不接受含义相同而字节已更换的记录。活动 view 的 reserve／clear 同样做原状态 CAS，另一个旧缓存 journal 不得覆盖；单项完成保留另一项及 UNKNOWN 顶层；最终只有旧缓存已空才按原 Android 同目录同步文件、rename/unlink、同步父目录流程移除。异常锁存，不以旧 bytes 重试或无条件恢复缓存。
- 现有 A 的 service lease 只允许原服务线程读写／切换／关闭，拒绝同步回调重入，可单次创建一个拆分视图，此视图不会自行解锁，只有校验原调度已空、旧缓存无记录且 marker 是空或合法 split 时才切换，拒绝切换不改变原模式；成功创建后旧 writer 永久关闭；服务 drain 的释放顺序不变。本切片没有在生产调度里打开该视图，没有迁移正常数据或启用任何并行发包。下一切片 C 必须先满足实际调度／恢复例程与真实 Android 验收。
