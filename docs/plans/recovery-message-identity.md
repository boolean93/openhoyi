# 恢复提示与资源身份

本阶段延续native-language-runtime-audit.md第3项已授权工作；不开放语言切换，也不改变共享恢复规则。

## 实现

ShotRecoveryClearGate.resource只将原ShotRecoveryGate.clearBlock的三个枚举原因映射成相同资源ID或null。旧block接口仍在，调用resource一次后解析文字；输入、时间读取时点、优先级及共享策略调用次数保持。

Service将恢复等待事件用ResourceMessage保存；manualSafetyMessage不再缓存文字，改为私有manualSafetyResource及只读文字getter。六处警告赋值和两处清除保留原条件及资源/null值。七处服务内部存在性判断直接检查ID，无论译文为空与否都不会把警告当作已解除。公开文字getter仍供页面和通知显示使用。

notification缓存、刷新触发点、优先级、目标页面与按钮控制没有其他改动；本轮没有增加强制通知刷新入口或重新发送设备命令。以后语言Context接入时，仍须覆盖警告为空时的常驻通知标题/正文及通道名称，不可仅依赖warning字符串变化。

## 验证边界

新增resource接口测试先因接口未实现无法编译；一次全回归在新增测试漏传解析参数时失败，修正后重跑。保留原明确中文预期/1500ms边界/设备不匹配与优先级测试；新增状态×设备×地址×时效×手动运行矩阵，对比两显示接口并确认反复显示不清除磁盘pending记录。两个接口内部共享实现，矩阵比较本身不是独立行为等价证明；明确预期断言与源码核对共同提供证据。

另有noDisplay解析器测试：resource不得调用解析器；空显示文字仍对应非null阻止资源，pending保持。Service整份源码从eb180ae正向重放18项声明的显示/存在性替换一致；Gate整份源码仅包装旧接口及相同资源映射，协议和会话规则文件未改。

完整离线回归与三个APK构建成功，后追加的空译文测试再跑两变体。独立审查只检查源码，无真机试验；不能由此宣称全部语言体验或硬件安全已验收。其余返回String的gate、统一语言Context/偏好、通知刷新/通道、长文字/RTL和选择入口仍待接入。
