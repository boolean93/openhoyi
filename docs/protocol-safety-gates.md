# 原生版协议安全门禁

目标是让原生版对每一次设备写入都有可追溯的来源、参数边界和结果判定。旧版 App 的报文字节相同只证明编码一致，不证明机器会以相同时序执行，也不能保证任何软件在断线、进程被杀或硬件故障时一定停液。

## 当前允许范围

| 写入路径 | 离线证据 | 机器证据 | 当前边界 |
| --- | --- | --- | --- |
| HOYI 认证与同步时间 | 15 字节编码、密码脱敏、GATT 代次与就绪门禁；认证写入回调后必须收到新的 `0x83`；进入 READY 前的通知不会进入产品遥测或回读判断 | 固件 1.1.3 已完成认证并持续回报，实机记录中的 `0x83` 在认证写入回调之后 | 仅已验证固件进入 READY；其它固件不开放控制；认证后无新设置帧则超时失败 |
| BOOKOO 初始化与去皮 | 四包固定顺序、间隔、校验和归零确认 | 双连与两次去皮后归零通知已观察 | 不复用到其它秤；归零以新鲜通知确认 |
| 曲线启动与停止 | 三条采集帧及 200 条工厂临时帧、1,000 条快捷帧与旧版编码器逐字节一致；会话白名单与单次启动/停止检查；会话层在启动入队及实际发送前均要求新鲜、清醒且无阻断告警的待机遥测，过期或收到萃取帧即取消待发送启动 | 工厂快捷槽位 5、采集曲线 1 和 3 的受监护启动及手动停止有证据 | 目标重量自动停止、其余曲线与异常断链仍未实机验收；启动必须二次确认，失联时由用户检查机器并用拨杆停液；发送启动前同步保存未结束标记与咖啡机地址，进程重启后保留检查提醒并阻止新萃取；结果未知时仅允许重连原设备，原设备新鲜待机回报才可清除提醒 |
| 常用设置、每周睡眠、立即睡眠、预热、杯数重置 | 设置 593 帧、睡眠两包、预热 32 帧及固定命令与旧版编码器对照；会话层在入队及真正发送前复核新鲜唤醒待机、无阻断告警，睡眠计划两包各自复核；普通设置、睡眠计划、立即睡眠、预热和杯数重置在发送前同步保存设备绑定的跨进程未确认标记；结果未知时不自动重发；预热重启后只允许同机连接及显式取消恢复，解除提醒须新鲜清醒待机和人工核对 | 这些写入尚无逐项实机回读证据 | 只开放已建模参数；待机温度限定 0–100°C；已接受写入后的非零 GATT 回调视为设备结果未知；不能把 GATT 成功当设置生效；停止萃取与预热取消不受待机门禁限制；预热取消的 GATT 成功和随后待机均不是独立的取消确认，真机时序仍待验收 |
| OTA、恢复出厂、拉杆校准、排水、报警忽略、密码修改、其它秤 | 无足够的端到端安全证据 | 未验收 | 原生版不提供写入入口 |

其它秤的旧版解析已局部整理到 `protocol-core/src/main/kotlin/io/openhoyi/protocol/LegacyScaleCandidates.kt`：Acaia 的 `EF DD` 重量事件、Felicita 的前两字节重量、DiFluid 的明确 type-3 正值报文。只返回带原始帧的**候选读数**，没有 Android 调用方，不参与自动停液。合成报文测试仅证明旧版字段解释与输入边界；缺少真实通知、初始化/去皮回报及负值样本前，不能把候选读数升级为受信任遥测。DiFluid 旧版的其它偏移和字节序猜测分支保持未实现。

## 提交与使用门禁

1. 每次修改 `CoffeeCommands`、`DeviceSession`、`ExtractionController` 或任何真实写入入口，都必须运行 `:protocol-core:check :device-session:check` 和 Android 模块单测/构建。`protocol-core` 与 `device-session` 的 `test` 也已依赖自定义 `verify`，防止误跑空测试。CI 日志必须出现协议检查数和会话场景数，而不只看绿色状态。
2. 新增可写命令前，先从旧版实际调用路径取得参数范围、字节序、帧长度和校验，再为全部允许参数建立独立旧版编码对照。没有经旧版编码函数对照的命令保持不可写；没有独立读回字段的已开放取消命令只能报告传输结果，不能声称机器状态已确认。不能仅凭与已知 opcode 相似就推断安全。
3. 运行时只允许服务层构造结构化命令；会话层再次检查固件、曲线帧白名单和连接代次。设置写入要求新鲜已唤醒待机遥测，萃取或其它事务活跃时拒绝并发。断线、超时、已接受写入后的非零 GATT 回调或回读不符为失败/未知，不自动重放启动或设置；设置结果未知期间，仅保留人工停止、取消预热和重新连接等恢复路径，新 `0x83` 回报确认当前状态后才恢复其它控制。
4. 恢复真机验收后，按 `docs/alpha-acceptance.md` 对每一类写入记录「原版动作与报文 → 原生报文 → 机器屏幕/阀门结果 → 断线或失败处理」。一次成功不扩展为其它曲线、设备或固件已安全。先完成低风险的读回和停止，再考虑高风险设置。
