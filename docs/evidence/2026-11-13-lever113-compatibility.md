# 1.1.3 拨杆配方兼容依据与验收边界

本次依据官方客户端既有协议，将 1.1.3 加入 OpenHOYI 拨杆配方的精确版本集合。**这是客户端兼容依据下的放行，不是 1.1.3 固件保存分支或实机持久化已验证的结论。**

## 静态依据

本机只读提取的官方 HOYI 1.2.6 安装包 SHA-256 为 `26133c2ac8ecf3d5ee7682bafa6555b1c78836749c937477b05214a88d8ea238`。其中，`app-service.js` 的 SHA-256 为 `4ed90ea99240b7f37373cdb5c9df0bf315103ca7aea6aaab6f37b2c58dd564d7`。`copy2Hoyi` 与 `copyRelase` 及其调用路径使用现有 20 字节 `0x08` 帧，检查到的发送路径没有 1.1.4 最低版本限制。

布局为：命令、段数/压力/变流位、温度、双字节最大水量、首段模式与预浸时间、四段目标、首段流量、首段持续时间、其余三段流量、XOR。编码与现有 `CoffeeCommands.storedLeverRecipe` 一致。深烘 Bloom 变流示例为 `08c35c0046041428160000c806019000640000c4`；本次使用模拟传输断言完整帧，不将该示例设为产品许可条件。

官方路径在调用发送后即显示完成，不能提供保存确认。当前没有 1.1.3 固件二进制的相应存储分支证据，也没有本次真实 `0x08` 写入或完整配方回读证据。[已有边界证据](2026-11-12-machine-lever-recipe-boundary.md) 中的固件存储分析仅覆盖 1.1.4/1.1.5，不能外推为 1.1.3 已证实。

## 保留的限制

Mobile 与 DeviceSession 仅将精确版本 1.1.3 加入既有许可，不按版本大小自动接受新固件。原完整设置/新鲜待机、报警、安全事务、连接身份、队列最终出队验证、未知记录与不自动重发行为均保留；1.1.3 的未审查Ls与首段流量模式仍按原 `CustomCurveFirmwarePolicy` 拒绝。未知配方参数也仍受原范围限制。

原确认框明确说明覆盖配方、完整回读不可用及发送无法确认保存；传输成功不升级为持久化成功。没有新增机器地址、曲线 ID、Debug 开关或一次消费标记。
