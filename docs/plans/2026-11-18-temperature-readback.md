# 温度设置主动回读

- 需求与范围：修改温度或补偿后应在收到机器新设置报告时及时解除等待，不等待实际温度升降。缺失回读仍保留未知状态，但可在现有恢复弹窗请求一次同步；不得假报成功、自动重放控制或扩大自动重连。
- 来源：develop / 362fe878e5d0a497490c6a93463b5f3d18e5a23c。
- 工作分支：fix/temperature-readback，PR 目标 develop。
- 诊断：用户 dev144、固件 1.1.4 日志中六次设置（五次萃取温度、一次补偿）均 GATT 成功，6 秒后 UNKNOWN；后续手动重连的初始 0x83 才确认。当前 SettingsReadbackPolicy 仅支持锅炉开关和模式，温度未走主动回读；未知状态又阻止普通过期刷新。
- 实现：明确列出萃取温度、补偿、蒸汽温度、待机温度及其共用指令的待机延迟，复用成功写入后的限次认证时间同步（250/1250ms）。不更改控制字节、设备身份、活动/新鲜度门禁、6 秒期限、未知记录或仅锅炉允许的重连。现有恢复弹窗在原操作具备同步资格时提供“刷新状态”，与清除提醒独立。
- 验收：首个新匹配设置帧即确认；首个无报告时最多第二次同步；非匹配不能确认；6 秒后未知；显式恢复只同步一次；控制只发送一次；断开/旧操作/失败不得继续同步。沿用原锅炉及模式回归。
- 验证：JVM fake GATT 不代表实体机接受或真实恢复时延。按 scripts/create-pr 执行必要完整门禁，独立审查后普通推送，draft PR、精确 branch-policy/verify 通过再合入。无本机 AVD、无真实设备操作。
- 发布：本 PR 不发 APK/标签，不安装。交由主任务集成 Mock，保持原签名、递增版本、保留数据。
- 回退：代码 revert，无存储格式变化；保留未知记录，不卸载清数据。
- 断联边界：日志也含独立断联，但 status=0 不是根因代码，无法据此断言硬件或手机故障；本改动不声称修复射频/系统断联。
