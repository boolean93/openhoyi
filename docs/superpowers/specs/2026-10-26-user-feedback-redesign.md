# 用户反馈改版设计

状态：用户已授权按全部反馈执行；Astra负责设计与验收，Sol开发。本文件是可执行设计，不增加形式确认门槛。基线 `f88f0de47078f50d3a8bd301553c69f19b1a9f6b`。旧方案不能覆盖 `docs/git-workflow.md`。

## 结果与结构

首页回归机器状态。主界面由一个 `MainActivity`、一个常驻导航壳、六个真实根 Fragment（首页、曲线、历史、豆库、秤、设置）组成。萃取是首页域的独立 Fragment 路由。本轮六顶层与萃取进入壳；低频二级编辑、详情和设置可暂留Activity，但不再显示顶层rail；不把 Activity 的 View 搬进 Fragment，不用 Activity 任务栈实现 Tab。系统授权、文件选择、分享等外部 Activity 不在此约束内。

Tab 使用稳定 tag 恢复 Fragment，首次点击懒创建；切换时 `show/hide`，当前页 `RESUMED`，隐藏页最高 `STARTED`，隐藏页停止 UI 轮询和焦点操作。壳集中绑定服务，页面只观察状态、请求业务操作。BLE、计时、采样、保存、停止保障继续由 `MobileService`/session 持有，页面销毁不能取消萃取。

保存每个 Tab 当前子路由、列表筛选/滚动、未保存编辑草稿、选中配方、图表参考曲线。旋转、主题/语言重建后恢复；进程死亡后从服务/持久层重建事实，不恢复为虚构的进行中状态。普通切 Tab 不进入返回栈，返回先退当前子页，再回首页，再退出；运行中的萃取通过常驻入口返回。

## 布局与视觉参数

沿用现有中性底色与橙色操作强调，避免另建一套主题。画布边距 16dp（宽屏24dp），相关元素间距8dp、分组16dp；卡片半径12dp，只对真正独立的区块使用卡片。标题22sp、分组16sp、正文14–16sp、关键温度/萃取数值28–36sp；所有交互至少48×48dp，图标24dp。

横屏宽度至少600dp且可用高至少360dp时使用左rail；2026-10-28实机反馈后改为104dp及下节间距，替代旧80dp/48dp密排。六目的地仍直接可见，图标与可见文字同时存在。操作区与导航分隔，睡眠和秤连接不是伪Tab。高充裕时底部纵排睡眠和秤状态；紧凑高时用固定顶部状态条承接这两个操作，六目的地仍直接可见。本轮仅手持设备和平板横屏，不新增竖屏布局或两行导航。任何布局都不可把睡眠、秤状态、停止萃取藏进滚动区。

首页首屏顺序：

1. 紧凑机器状态行：设备名、连接/重连/断连/睡眠状态、连接动作。
2. 双锅炉区并排：萃取锅炉温度+开关，蒸汽锅炉温度+开关。温度大字，目标温度次级；写入中明确等待，回读成功才呈现已生效。
3. 快捷萃取：当前配方摘要及启动主按钮；已有五个合法预设槽直接可选。曲线选择仍是一跳。低频豆信息、准备说明和历史摘要不挤占首屏。

温度只来源于已验证遥测。`IdleTelemetry` 可显示双锅炉；`ExtractionTelemetry` 不提供蒸汽温度，必须显示“—”或明确“上次读数”，不能把萃取温度重复充当蒸汽温度。开关复用设置写入门禁及回读。快捷启动调用与原 `ExtractionActivity.confirmStart` 相同的校验和确认路径；不扩展 `PresetSlots` 的 `factory-v3-001..100` 五槽支持边界。

rail常驻区：睡眠和秤状态须有可见文字；连接/断开用文字动作，禁止再以月亮、绿点秤和 `×` 三个纯图标替代含义。秤状态入口保持可点，设备名称可在秤页及无障碍描述完整提供。具体状态与尺寸按下节执行。主动断开必须进入抑制自动恢复状态，禁止瞬间反连。机器活跃/未知写入时按钮明确不可用原因。

## 萃取大图

只保留一张共同时间轴的大图，压力、注水、出液（仅在具备有效杯重基准时；否则明确标为“秤读数”）和温度同时可见。图上方一排指标兼图例；横屏主图占剩余内容宽度至少70%，不保留280–320dp无效说明侧栏。下方固定开始/停止及单行状态。配方/参考线/高级工具通过紧凑次级入口展开，不挤占图高。标准横屏可用720×360dp时主图绘图区目标至少180dp高；常见平板至少260dp。低高度和字体放大优先保留停止、实时数值、图，再滚动低频信息。

本地官方参考是只读 `analysis/readable/app-service.js:69849–69898`：四条同图、无点标记、无动画、2px线、低透明填充、极少额外装饰。`22897` 配色为蓝/橙/绿/紫，但原语义为压力/水流/咖啡流/重量，并非本次四指标，不能照搬语义。本次设计采用压力蓝 `#2F80ED`、注水橙 `#FF8A3D`、出液绿 `#27C47A`、温度紫 `#7B61FF`，浅色模式按对比度加深。实线2dp、参考线1.5dp虚线、填充透明度最多0.08、网格1dp低对比、无曲线动画。

保留 `FourMetricChartProjection` 真实量纲、分段缺失、负重量、注水复位和范围只扩不缩规则。各量纲独立映射，左轴显示选中指标单位，图例持续显示每项范围；选中图例只切换轴/强调，不隐藏其他指标。必须说明“独立刻度”，不制造同量纲误导。不插值抹平断点，不把注水量当出液量，不把原始重量虚构成归零净出液。

## 设置与弹窗

设置根页为机器、秤、App三组，固定分组入口与两栏布局（窄屏单栏），参数行统一为名称、当前值/单位、状态、编辑入口。所有现存功能必须可达，包括睡眠计划、杯量、温度校准、外观、语言、反馈、通知和历史导入相关项。机器相关设置无连接时显示原因，不能隐去入口。

统一全部 App 自有 AlertDialog、PopupMenu、选择器、图表检查和确认弹窗。统一标题20sp、正文16sp、间距16/24dp、圆角16dp、按钮48dp、最大宽560dp且不超可用宽减32dp，长内容只滚动正文、底部动作固定。危险操作强调明确动词，不用笼统“确定”。启动/写入/未知结果的原确认语义保留。系统蓝牙权限、系统文件选择、系统分享面板保持平台外观。

## 手动萃取与恢复

使用服务 `PassiveShotDetector` 已确认的手动新杯事件，不直接用瞬时拨杆值或页面轮询推断新杯。服务暴露稳定手动杯ID或单调序号，壳记录 `lastPresentedManualShotId`。应用前台检测新杯，原子记录已展示后切到萃取曲线；同杯后续遥测、切Tab、配置重建均不抢回。新杯再次触发一次。后台只记录待处理事件，恢复前台仅在该杯仍活跃且未展示时跳转；不从后台强启Activity。

机器/秤意外断开后只恢复已保存且已授权的原设备。每个角色独立维护 desired-address、用户主动断开抑制、当前连接世代及有界退避；恢复广告匹配/连接/订阅/只读同步，不重发开始萃取、去皮、计时、设置、睡眠或未知结果操作。机器真实唤醒后的可连接状态可触发恢复；不能臆造唤醒写命令。不可在切Tab时断开或重新连接。

BOOKOO 已证根因：初始化 `030A0700000E` 为去皮并计时。批准仅删此帧，保留其余三帧及500/1000/2000ms时间点；不额外发stop/reset。初始化白名单同步不再放行该帧。独立Sol负责实现和真实连接重连写帧测试。

## 官方依据与应用取舍

- [Android Fragment lifecycle](https://developer.android.com/guide/fragments/lifecycle)：Fragment和View各自有生命周期、支持maxLifecycle；本设计据此明确清理View订阅，不把服务生命周期绑定页面。
- [Android navigation rail](https://developer.android.com/develop/ui/compose/components/navigation-rail)：rail用于大屏3–7个顶层目的地；本项目六项适用，仍采用现有View技术而非引入Compose。
- [Apple Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)：顶层切换保持各区导航状态、入口可见、导航与动作区分；据此取消“更多”隐藏高频项，把睡眠/连接放入独立操作区。尺寸和配色是本项目设计决定，并非声称来自平台强制规则。

## 完成边界

软件完成需原生运行截图/控件几何、导航生命周期、业务门禁回归证据。Mock只验证布局和状态机，不能证明机器关锅炉、停止出水、唤醒重连或秤不计时。没有实机证据的项在验收记录明确待实机，不写“已完全修复”。本次由主协调者在现有feature分支普通提交并推送既有PR，不合并、不发版、不安装或操控真实机器。


## 2026-10-28实机侧栏修正：间距与明确设备操作

依据`build/device-install-2026-10-28/installed-mock.png`实际图及三类壳源码。实机2560×1600、density2.25，约1138×711dp，系统insets后可用高约667dp。现版80dp rail、图标20dp、图文间距2dp、项内上下1dp且无项间距；底部月亮/绿点秤/X只在contentDescription说明含义，目视不可理解。此前代表图的有限批准不能覆盖本次用户实机反馈，本节取代旧密排参数；不改变侧栏方向、目的地、协议或业务门禁。

选择104dp文字侧栏方案。仅80dp加边距不能同时容纳标签与设备动作；整套横向展开的宽侧栏会无必要占用主图。本次适度增加24dp，沿用现有主题、选择底色及图标，不另起风格。

**常规横屏参数**：rail宽104dp，左右内边距8dp；导航项宽88dp、最小高60dp，图标24dp，图文间距8dp，文字14sp、基准20sp行高（fontScale1约20dp，随字体缩放扩展）、至少上下各4dp。项间8dp，导航顶部/底部各8dp。六项固定顺序，前四项与秤/设置之间允许弹性留白，但不挤压上述最小间距。选择态仍为单个柔和色块；不为所有导航加边框。六项最小预算`6×60 + 5×8 + 16 = 416dp`。

**设备区**：与导航间留12dp并加低对比横分隔线；左右8dp、顶部/底部各8dp。睡眠按钮最小56dp，秤状态入口最小56dp，独立秤动作最小48dp，两处间距8dp，中文fontScale1预算192dp。控件均wrap_content且只设minHeight，长翻译/大字自然增高；TaskPageFrame必须先测实际设备区再决定位置，不能拿192常数作适配依据。设备区不另加标题。导航+分隔+设备约620dp，实机可用约667dp，约47dp用于组间弹性留白。实际以字体/文案测量为准，禁止固定620截断长字。睡眠为轻描边双行操作按钮；秤状态为无边框双行文字入口，状态点只作辅助；秤连接/断开为轻描边文字按钮。与导航选中块明确区分，不保留三个相同大边框纯符号按钮。

| 写入/等待回读/未知结果 | “咖啡机睡眠”/“等待确认”或“结果待确认” | 按真实tracker细分，原禁止重发保持 |

设备区104dp扣外侧16dp和Button内侧16dp，文字净宽72dp；正常标题“咖啡机睡眠”5汉字约70dp，已睡眠状态避免六字长标题。所有状态/按钮14sp起、基准20sp行高且随字体扩展、无省略号；辅助状态不能只放无障碍描述。活动萃取下连接/断开按现有规则禁用，仍显示动作文字，不隐藏连接事实。双行是短文案目标而非maxLines=2硬上限，有限宽度可自然增高，不能压成12sp或消除8dp图文间距。新增文字进入现有本地化资源；设备真实名称保留在入口无障碍描述/现有秤页，不伪造。

**短高降级**：优先依据真实测量判导航+设备是否放得下。放不下时将同一设备区移至既有pageContent顶部固定横条（沿原fallback），高度至少56dp：咖啡机睡眠双行组、电子秤双行状态组、独立连接/断开文字按钮，组间8dp。不把任何设备状态放进滚动/更多菜单。若六个竖向图文导航项本身仍放不下（如720×360），保持左104dp侧栏及六项目的地顺序，将每项内容改为20dp图标+8dp间距+14sp文字同一行；点击高48dp、项间8dp、上下各8dp，共344dp。344dp指frame扣除系统insets后的实际可用高；若物理360dp设备扣insets后不足344dp，仅允许现有导航滚动区滚动访问六项，设备状态条与停止仍固定，不压小点击区/字体/间距。六项全可见承诺适用于实际可用高至少344dp。这只调整项内排列，不改Tab方向或删除秤/设置。原Home高频首屏及固定停止门禁保留；若文字放大仍溢出，先增加真实测量预算/使用现有降级位置，不能删文字换回纯icon。

**实施与验收边界**：Sol只改TaskNavigationView（间距/项内两种密度）、TaskShellStatusView（可见文案/分组）、TaskPageFrame（104dp和真实预算切换）及必要资源/现有断言。保持原Fragment、服务、点击回调、sleep/write/active门禁及未知记录；不得为了展示“唤醒”新增命令。验收看本台实机正常高度浅深原图和现有720×360两态：六导航图文间隔/点击至少48dp、设备状态和文字动作完整、明确禁用原因、无底部裁切；运行图仍守常见平板真实网格260dp和停止完整。先交实图供Astra复核，旧纯图标/80dp精确断言应按本明确新合同更新，业务断言不放宽。不增加页面/测试矩阵。
