# Preflight tare dispatch activity guard

Observed gap: the target-weight preflight tare closure checks original serial/STARTING, deadline and original coffee context, but not lastActiveFrame. After unexpected valve activity and subsequent fresh idle, the original coffee context can again be eligible and a still-queued tare may zero a manually active cup. Add lastActiveFrame==null to this actual-dispatch predicate. Do not change the optional flow-only delayed tare, packet bytes, deadlines, cancellation/unknown behavior or stop gates.

Tests use actual CoffeeSessionFixture, genuinely initialized BOOKOO DeviceSession, StandaloneTare, ScaleSessionControl, CoffeeSessionControl and ExtractionController. A fake Discover lifecycle barrier holds the scale queue; coffee activity reaches the Controller and actual Session, then fresh idle restores original protocol eligibility. Positive clean/closed-valve cases verify exact tare bytes then newer decoded zero before exactly one original start. Also exercise unexpected activity after tare already dispatched without retroactive retry/clearing.
