# 1.1.3 临时跟随及全局慢速：官方客户端兼容依据

用户明确选择官方 App 对等兼容。精确版本 1.1.3 获得临时完整压力跟随 0x02 和全局慢速 0x03 许可；这不是固件控制、阶段退出或物理停水已验证的声明。1.1.4/1.1.5 原始固件离线证据保留于 [此前记录](2026-11-13-official-control-modes.md)。

## 原始客户端路径

只读官方 Android 1.2.6 `app-service.js` SHA-256 为 `4ed90ea99240b7f37373cdb5c9df0bf315103ca7aea6aaab6f37b2c58dd564d7`。以下 offset 为 UTF-8 解码后的零基字符位置（压缩源码行仅 14/21）。

- 首页 pSwChange / fSwChange：行14，offset 843411 / 843645，直接调用 setPress(pressMode, flowMode)，未读固件版本。
- setPress：行21 offset1566782，原源码日志 common/bluetooth.js:1408，编码 `03 02 press flow 00`；慢速为 `0302000100`。
- 曲线模式 UI：行21 offset1612303 / 1612536 / 1613031，分别更新 press / chart / seg1FlowMode；commitCurveFieldsToHoyi 在1616072。
- startRelase：1619204，chartlib.vue:2119–2143，调用 startTempChart(7,hoyi,1)；startTempChart 在1564571，bluetooth.js:1294–1387，无最低固件版本判断。完整20字节0x02中的byte1 bit7/6是press/chart，byte5 bit7是首段流量，其他目标、流量和时间字段沿用原编码，byte19是XOR。
- 全部 swVer 引用出现在初始化、接收解析、展示、OTA，不在这两条发送路径设置最低版本门槛；对应 UI 开关也未因版本隐藏。

这证明官方客户端对已连接的 1.1.3 使用相同编码路径，不能证明每个参数或固件内部行为。官方 BleWrite 失败重发、255秒等宽松范围不照抄。

## 精确范围与保留保护

1. 临时跟随仍限定既有完整压力配方参数范围、槽7；共同前置验证仍在 legacy 帧及主机许可之前。
2. 0x08 持久跟随所有版本仍拒绝；1.1.3 的 Ls 曲线及首段流量限制不随本次扩大。首页全局慢速与完整流量配方是不同路径。
3. Unknown/null/1.1.2/1.1.6 不获得新许可；设置、待机新鲜度、报警、并发事务、派发身份和固件变化重验不变。
4. 保留新回读确认与未知结果，不将 GATT success 视为执行或保存成功，不自动重发未知结果。

未取得 1.1.3 原固件；原 OTA 地址返回404，APK嵌入 App.bin 是不匹配的旧设置帧布局，不拿来替代1.1.3。此次没有硬件测试、安装、刷机或真实萃取。后续现场异常反馈继续按具体模式排查，不宣传为已实机验收。

## 后续完整流量组合补齐

基于同一官方客户端路径，1.1.3 临时 0x02 的 Ls 和首段流量组合也获得许可，取代上文第2项中对临时执行的限制。仅精确版本和原有效参数范围变化；不把固件控制/停水视为已验证。`permitsStoredRecipe` 独立保留 0x08 原边界：所有跟随禁止、1.1.3 Ls/首段流量禁止，并先于 legacy 帧/主机许可执行。Mobile 在记录写入事务前给出专属持久限制提示。计划见[完整流量兼容](../plans/firmware113-flow-compatibility.md)。
