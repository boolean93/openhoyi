# 旧版萃取历史导入

原生 Alpha 的历史页提供“导入旧版历史 JSON”。输入必须是旧版 UniApp 存储键 `brew_history_v1` 的完整 JSON 对象，顶层格式为 `{"version":1,"items":[...]}`。旧 App 记录来源和字段依据：`hoyi-project/app/assets/apps/__UNI__7D80DAB/www/app-service.js` 的 `common/brew-history.js` 模块。每条旧记录含 `id`、`createdAt`、`durationSec`、`chartSlot`、`profileName`、`snapshot` 和 `points.{t,press,flow,wFlow,wTrend}`。

旧包私有存储不能由新包直接读取。已修改的旧版 HOYI 在协议记录浮层菜单中提供“导出旧版萃取历史 JSON”：先在保存历史的旧版安装包内打开该菜单，导出并通过系统分享保存文件；随后在原生版“历史”页点击“导入旧版历史 JSON”，从系统文件选择器选取该文件。导出只读取当前旧版安装包的 `brew_history_v1`；不同包名的原始版数据不会自动转入修改版，若数据只在另一个包里，仍须从那个包单独取得。原生包通过系统文件选择器显式导入。原生包只读文件内容，不访问旧包目录，不发送蓝牙命令。导入在后台运行，限制16 MiB、每次最多2000条、每条最多2000点；版本、ID、时间顺序、五组等长数列或数值异常时整批拒绝，已存数据不变。重复导入相同 ID 和内容不产生重复记录，同 ID 内容冲突也整批拒绝。原始 `snapshot` 与五组点数组在独立 `legacy_history.json` 中保留，原生历史不受影响。

“查看旧版历史”是单独的只读页面。图表仅绘制单位有依据的旧版压力（bar）和机器水流（ml/s）。`wFlow/wTrend` 在旧代码中经过基线、裁剪和平滑处理，保留原始数值，但不伪装成原生秤重或咖啡流速；旧记录也没有原生的机器温度、累计水量、BLE 传输结果和结束确认。导入只重现旧 App 已保存的记录，不证明当时机器执行成功，也不参与新 App 的萃取控制或原生历史 ZIP。

离线单测使用按旧版保存代码构造的合成 JSON；旧版导出菜单的分享链路也有单测。尚未拿到用户真实 `brew_history_v1` 导出文件，也未安装原生 Alpha 验证系统文件选择器。取得真实文件后，应先在 Mock 包导入并核对条数、时间、曲线与重复导入，再在 Alpha 包导入。
