# 旧版曲线库迁移边界

已修改的旧版 HOYI 在协议记录浮层菜单中提供“导出已保存曲线库 JSON”。它读取当前安装包私有存储的 `hy_chartLib`、`hy_factoryChartVer` 和 `hy_chartCatConfig`，写出 `openhoyi-legacy-curves-v1` JSON，并通过系统分享面板保存。尚未保存到 `hy_chartLib` 的编辑不在文件中。导出的 `items` 是整个旧版数组，包含用户曲线、工厂曲线、原有顺序和未知字段；不会按名称推测哪些曲线是用户自定义。不同包名的旧版安装包之间不能互读私有数据，必须在实际保存曲线的那个包内导出。

原生版在“曲线库 → 旧版曲线 → 导入旧版曲线库 JSON”中通过系统文件选择器导入。格式和16 MiB/2000行上限先校验，失败时原有文件不变；成功后原子替换独立的 `legacy_curves.json`。重复导入同一文件不改动数据。列表按旧版位置显示，分类名称采用旧版导出的配置；详情只展示温度、水量、目标重量和分段数等原始字段。源 JSON 完整保存，未知字段不会被丢弃。空槽位也保留位置。

导入曲线**只读**，没有“设为当前曲线”或快捷槽位入口。它们没有进入 `CurveLibrary`、`FactoryWireProof`、`MobileService` 或 `DeviceSession` 的启动许可集合，也不发送 BLE 命令。旧版曲线编辑器的字段可能是字符串、缺失或经过迁移；仅凭展示数据不能生成安全启动帧。未来要开放萃取，须取得用户真实导出文件，对每条目标曲线的有秤/无秤旧版 `startChart` 报文逐字节对照，并复核参数边界、槽位和机器回报。

目前只有合成文件的离线测试与旧版分享链路测试，没有用户真实导出文件，也未安装两个新构建验证系统文件选择器和分享面板。取得真实文件后先在 Mock 包核对条数、顺序、分类与参数，再考虑控制路径。曲线编辑仍按用户要求后置。

## 离线启动报文证据

取得真实导出文件后，可在开发机运行：

```sh
python3 scripts/generate_legacy_curve_oracle.py /path/to/app-service.js /path/to/hy_chartLib.json /path/to/proof.tsv
```

脚本仅提取旧版 `startTempChart` / `startChart` 及其编码辅助函数，在隔离的 Node VM 中执行，不启动旧 App，也不连接蓝牙。它将导出文件的 SHA-256、旧版 bundle SHA-256 和已审查编码函数的 SHA-256 写入证明头；编码函数变化则拒绝。每个非空曲线位置生成临时槽位7及快捷槽位1–5的有秤/无秤共12条报文。任一位置不能生成单条合法20字节帧时，整份证明不会发布。空槽位跳过，但不改变后续索引。

`python3 -m unittest scripts/test_legacy_curve_oracle.py` 用已验证的100条工厂曲线资源核对1200条旧版启动帧，并检查格式错误、编码函数改变和空槽位。这个 TSV 是**旧版发了什么**的离线证据，不是原生控制许可；还需将真实用户曲线逐项转为原生参数，与原生编码器逐字节比较，并按导出文件哈希绑定后，才能讨论开放启动。

原生版已有独立的 `LegacyCurveAdapter` 用于**离线比较候选参数**，不由 `CurveLibrary` 或服务层调用。它只接受完整、无歧义的整数字段及布尔模式，保留旧版 `seg1FlowMode` 的条件位；缺字段、模糊字符串、越界参数或空槽位均不能转为候选。单测用100条工厂曲线的1200帧及一条开启首段流量模式的旧版向量核对。候选可编码不等于可启动；真实导出文件仍需逐项与上面的旧版 TSV 对照，且尚无用户数据完成这一步。
