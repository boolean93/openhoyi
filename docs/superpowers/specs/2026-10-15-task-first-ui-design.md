# HOYI 任务工作台 UI 设计规格

2026-10-15。状态：用户已在本会话书面审阅请求中回复“按此进入实施规划”，整合规格获确认。进入实施规划；应用改版仍须逐项实现和验证，不以确认代表完成。

## 1. 目标和范围

把当前同权重大按钮、重复入口、含义不清的图表，改为围绕一杯咖啡的任务工作台。优先简体中文和用户的小米 M2105K81AC 平板。不是只压缩旧布局，也不是只交截图测试。

范围为[页面索引](../../research/task-first-ui-concepts/index.md)列出的全部21个非设置页面；三个设置页继续保留全部功能，采用相同导航、字号和控件层级，但不强制设置内容单屏。主页面不能整页滚动，长列表、图表探索和表单编辑可以局部滚动。曲线库连续滚动，不分页。

本轮不新增蓝牙协议、控制算法、配方预测、云同步、社区、库存字段或评分模型。已有高级功能必须保留，不能借UI重构删掉。设备控制、未知结果、库存幂等、导入格式、数据库与签名升级策略不是视觉层可以重写的内容。

## 2. 依据和已确认决策

采用[Google自适应导航](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns?hl=en)和[标准布局](https://developer.android.com/develop/ui/views/layout/canonical-layouts)的导航轨、列表详情和主辅区模式；采用[Apple布局](https://developer.apple.com/design/human-interface-guidelines/layout)、[按钮](https://developer.apple.com/design/human-interface-guidelines/buttons)和[图表](https://developer.apple.com/design/human-interface-guidelines/charts)指导的信息层级、操作区分和明确量纲。这些是项目设计依据，不是把Apple控件或材质移植到Android。

用户已明确认可「左侧导航＋冲煮工作台」，授权继续细化；最新补充要求满配萃取图为压力、注水量、出液量、温度，覆盖先前压力＋流速的默认组合。官方资料、备选方向与历次稿件见[研究草案](../../research/2026-10-15-task-first-ui-redesign-draft.md)。

## 3. 信息架构与任务路径

固定主目的地顺序：**冲煮 / 曲线 / 记录 / 豆子**。电子秤是独立工具，设置为低频工具。导航只放目的地，不放开始、停止、归零等动作。

- 准备：确认本杯曲线、豆款/粉量和设备条件。曲线预览为阶段目标，不是未来萃取时间轨迹。一个主操作“开始萃取”，仍进入既有启动确认与门禁。
- 运行：当前时间及有效出液量优先；无秤且原模式允许运行时，主数量改为注水量。压力、温度其次，大图居中，停止固定。运行页不摆库存编辑、曲线选择等无关入口。
- 结果：展示实际观察到的结果、历史曲线、本杯信息，再进入复盘。未知结果不能自动变成结果成功页。

曲线库选择“用于本杯”只更新原本允许的本杯选择，不自动发命令。从记录、库存等页返回冲煮时保留同一杯上下文，不新建控制会话。用户可以离开运行页浏览；离开页面不等于停止，返回也不等于再次启动。其他页面若已有持续安全提示，仍需可见；不得因新壳隐藏。

准备工作台必须有明确文字入口“设备连接”，不能只让用户猜状态芯片能否点击。它打开保留原功能的局部设备面板：扫描/权限/候选连接、固件与告警、拨杆/睡眠及其原确认、机器设置、断开机器/秤、秤重/去皮状态、停止设备服务。低频内容可分组和局部滚动，不能从新导航中消失；“停止设备服务”与“停止萃取”不能混名或混用。原手动安全恢复入口及按写入类型区分的确认文案必须保留，只在原门禁允许时调用，不把关闭提示当成清空未知记录。

原快捷曲线1–5槽位保留：准备页“快捷曲线”入口显示全部已绑定槽位与名称，选择后只进入对应槽位的准备状态；曲线库工具栏保留“绑定快捷槽位”，沿用原工厂曲线与可执行条件。普通本杯选择和槽位选择仍是不同来源，不把槽位身份写丢。

## 4. 共用视觉和操作规则

| 元素 | 规格 |
|---|---|
| 背景/内容 | 浅暖中性背景，深色文字，细分隔，少阴影；不把所有字段做独立大卡 |
| 字号 | 正文16sp，辅助14sp，标题24sp；实时主值初始40–48sp。尊重系统字号，不用缩字规避溢出 |
| 间距/圆角 | 8dp间距体系，容器12–16dp圆角；相关内容靠近，无关组留空间 |
| 触控 | 可操作目标至少48dp；可见图标、文字和边框可以紧凑，不代表所有按钮铺满宽度 |
| 主操作 | 每个任务状态最多一个主要正向动作；纯只读页面可以没有填充主按钮 |
| 次操作 | 工具栏、文字或描边；不让导出/更多/新增和当前任务同时抢主色 |
| 停止/危险 | 停止固定、标签和图标明确；正常库存耗用不标危险红 |
| 状态 | 图标/文字/颜色共同表达；已连接不等于数据实时；空态、加载、读取失败分开 |
| 长内容 | 列表摘要可省略，但完整内容入口明确；编辑原文不可截断或丢失 |
| 深色/无障碍 | 共用语义色资源，深色不是简单反色；文字及图形对比、TalkBack名称/状态/焦点在真实控件验证 |

装饰豆子照片、无数据含义的彩色方块和重复说明删去。不新增用户原本没有的数据字段去填空白。概念稿上的“设计示意”“演示数据”和虚构设备说明不直接进入正式产品；Mock如需模式提示，沿用真实构建模式标记。

## 5. 萃取图表

完整来源与异常规则以[图表能力规范](../../research/2026-10-15-extraction-chart-capabilities.md)为准，以下为本轮不可删减要求。

| 默认指标 | 单位 | 来源 | 线型 |
|---|---|---|---|
| 压力 | bar | 有效机器采样 | 蓝实线 |
| 累计注水量 | ml | 机器累计水量字段 | 青长虚线 |
| 出液量 | g | 有效秤重及杯重/归零上下文 | 深青实线/点 |
| 温度 | °C | 机器萃取温度采样 | 琥珀点线 |

四项在**同一个绘图区、共用时间轴**，各自按明确物理量刻度投影。流速ml/s、g/s可作为已有高级信息保留，但不替代这四项，不默认塞入第五、第六条线。新图必须由真实数据绘制，不能把生成图片作为背景，也不以图片里的端点反推数据。

### 数据与量程

1. 注水不由流速积分猜测；出液不由注水推测。机器累计字段若重置/回绕，标记边界，不擅自累加“修复”。
2. 无秤时机器三项继续显示，不画0g或无依据重量。中途无有效秤数据时保留有效历史片段，当前显示“—”和原因；恢复后不得跨缺口连线。杯重基准不明只能称“秤读数”，不得自动归零。
3. 机器数据过期时相应实时值为“—”，保留已采样片段，不用最后值伪装实时。若只有采样缺口证据，就标缺口，不能虚构具体断连原因。
4. 时间只代表已知采样或已知运行状态。最后采样时刻不能标成当前时间或结束时间。本杯未来不画曲线，不延长最后一帧；用户显式选择的真实历史参考可以展示其已保存的完整轨迹，但必须标明参考身份，不能伪装为本杯未来预测。
5. 压力既有非萃取阶段断点继续保留，不强行连成平滑曲线或补零。抽稀不能抹去断点、峰值或来源差异；显示变换不改原始存储。
6. 每杯量程尽量稳定，超出时扩展，不裁峰、不强制负值归零。温度概念稿80–100°C不是实现截断范围。图例当前值和对应图上最后有效值同源。
7. 原生历史缺少有效杯重证据时称“秤读数”。旧版历史只显示有明确来源的压力bar与机器水流ml/s，不补温度、累计水量、原生秤重或结束确认。
8. 图表温度的原始/修正来源必须明确。现有保存字段为机器温度；图例与该曲线用同一采样值。准备页既有校正温度和控温判断保持原来源；需要同时解释时标为“已修正温度”，不把它与原始历史采样混为同一值，也不重写历史。

### 图表交互

大平板默认显示所有有效系列，左右各列独立量纲刻度。图例支持显隐或突出指标，只改变显示，不改采样、配方、自动停止或记录。点击/键盘聚焦某采样时刻提供同一时刻的可用数值；缺失值仍为缺失。屏幕阅读可达时间、指标、单位及缺失原因，不要求通过视觉猜曲线。

两杯对比一次聚焦一个指标，两杯同尺度，实/虚线区分；可切换四项，缺失系列说明原因，不默认叠八线。预设预览横轴是阶段1…4，不是时间；不从阶段参数猜未来完整压力/出液轨迹。

运行图的“选择历史参考”保留为明确文字工具入口，不藏在仅技术人员理解的图标里。沿用原同曲线、已结束记录及样本可用条件，当前候选边界为最近最多20条；支持关闭参考。保留按实际萃取起点/记录起点对齐的来源说明，不由配方生成参考。默认只叠所聚焦指标的参考，避免八线默认叠加；已有杯中流速参考仍可经“高级指标”查看，注明估算/来源和g/s，不替换默认四项。显示参考不改本杯采样或控制。

## 6. 控制状态与安全反馈

视觉层读取现有状态和门禁，不拥有蓝牙连接，不自建计时重试。`StopActionPresentation`及原`ShotGate`、去皮、准备、设置写入、睡眠和安全记录判定继续生效。

| 实际状态 | 用户可见内容 | 操作规则 |
|---|---|---|
| 未选/只读曲线 | 选择配方或仅预览的原因 | 无可执行配置不得开始 |
| 所需设备未就绪 | 未满足条件与明确处理入口 | 不能因图表有三条线绕过重量目标配方的秤门禁 |
| 预热/去皮等待 | 实际状态与原取消/恢复入口 | 不造倒计时、不把取消请求当已完成 |
| 可开始 | 配方/本杯用豆与实际就绪信息 | 点击后原确认、单次派发 |
| STARTING | 正在启动、保留上下文 | 不提前显示运行；停止由原判定控制 |
| RUNNING | 当前有效采样、四/三指标图 | 原停止可达；运行中不越权扫描/切换设备 |
| STOP_REQUESTED | 正在停止、等待停止结果 | 原位置的停止入口显示处理中且禁用；不自动重发，不声称已停水 |
| OUTCOME_UNKNOWN且机器未READY | 安全说明、无效当前读数、历史断点 | 停止不可用，提示检查机器；不提供“清记录后重试” |
| OUTCOME_UNKNOWN且机器READY | 仍是结果未知，安全说明保留 | 仅原条件满足时可由用户显式停止；不因重连自动发送 |
| ENDED_OBSERVED | 观察到的结果及复盘入口 | 不把软件观察等同物理设备验收，下一杯依原门禁 |
| 机器手动萃取 | 原“请用机器拨杆停止”等指导 | App仅记录的模式不能凭新红按钮假装可控 |

断秤是数据能力变化还是会触发停止，由既有控制层决定；不能依据图表继续画三项就擅自决定继续萃取。新UI不得弱化现有安全消息，不自动清除未知记录或恢复事件。

机器告警、告警数据过期和通知权限不足提示必须按原条件直接可见，不一并藏入配方详情；新安全提示优先级不能被正常就绪行覆盖。既有预热/取消预热、去皮等待仍保留独立状态与入口，不能合成“开始”后默默执行。

已有本地萃取趣味反馈保留为结果区内联提示，完整保留“趣味提示，不代表风味评分”的语义及重播入口，不挡住结果图和复盘。沿用原开关、READY/Idle/无告警/无未知安全消息等资格、一次领取和本地音频行为；旋转只恢复显示，不再自动播放，离开/关闭/资格变化停止音频。不能把这项既有反馈删掉，也不能把它升级成真实口感评分或云端评价。

记录页的工具栏按当前来源变化：本机记录提供ZIP导出与旧版历史导入；长期复盘提供JSON导出、显式“迁入最近记录”和两杯对比。迁入只使用已有观察，不覆盖既有笔记、不补采样；空态入口与存储失败分别处理。旧版只读子页不另造导入按钮，导入仍由本机记录入口发起。两杯对比还须保留每杯状态/未知提示、同豆/不同豆/未知豆与同曲线/不同曲线说明、两杯详情及完整笔记入口；样本缺失或读取失败不假装为零线。复盘豆子选择还须保留原记录中的豆ID/名称，即使该豆已不在当前库存列表，不能因重建选择器就清空。

## 8. 表单、库存和数据恢复

输入使用原生控件，单位固定在字段标签/后缀；研磨是自由文本，没有强加圈/档单位。日期允许按原规则留空，格式/数量错误显示到对应字段组，不先丢草稿再报错。键盘、旋转、切组、文件选择往返保留字段原文、选择身份、焦点/光标和列表位置。

长表单是有边界的内部编辑区，主操作固定在编辑区外、键盘上方。大屏尽量内联，不逐字段强制弹窗。正常短表单限宽，不增右侧说明墙填充空间。长名称可完整查看和编辑，不能把显示省略后的字符串写回。

库存仍由独立模块负责，UI不在onResume、重建、图表重绘或保存复盘时扣豆。既有“选择→显式确认耗用→幂等记账/关联本杯”流程保留；一次耗用身份跨失败恢复保持，不另造事件重扣。未尝试的选择取消与已尝试后的恢复/弃置严格沿用原语义，不把结果不明的写入当未发生。

库存调整的输入是调整后的实际余量，不是增加/减少量；系统计算差值，预览当前/目标/差值和原因后再显式确认。提交前余额若改变，沿用原复核失败与重新预览路径，不直接应用旧差值。流水模型只有事件ID、批次、类型、变更、余额和可选原因，没有时间戳或永久的萃取归属；不从UUID、批次购入日、当前时间或当前选择猜日期/本杯来源。后续若要事件时间，属于独立数据模型与兼容迁移，不混进本轮UI。

分享只在用户明确动作后打开系统交付界面；不自动外发。导出文件未完成不能标成成功，文件分享仅在有效导出URI存在时可用。导入先解析和预览，再显式保存，不自动选中或执行。

## 9. 响应式规则

> **2026-10-16 用户范围变更（优先于本文旧竖屏要求）**：不再要求兼容竖屏。以用户平板横屏2560×1600、density360优先验收，保留横屏大字号、IME/短高和任务/安全完整性。以下窄宽度布局仅保留为现有回退或横屏分窗参考，不要求额外竖屏交付；历史竖屏概念稿不再是验收项。未要求强制锁定方向，本轮不改manifest方向。完整变更见[横屏范围计划](../plans/2026-10-16-landscape-only-scope.md)。


按可用窗口而非设备名或仅横竖屏判断。历史设备证据是1600×2560、density360，约711×1138dp（尚未扣系统栏）；不是这次重新测量或实机验收。

| 条件 | 布局 |
|---|---|
| 宽度≥840dp且主辅区满足最小内容宽度 | 72–80dp导航轨；集合列表-详情；运行图约七成，配方辅助区约三成 |
| 600–839dp | 导航轨保留；运行图上下布局，配方变短条/详情入口；集合使用列表→详情，返回恢复选中/位置，不强塞两栏 |
| 宽度<600dp | 四目的地底栏；电子秤/设置由明确“工具”入口到达；保持同一状态和选择，不另建会话 |
| IME/大字号导致高度不足 | 缩去装饰logo/多余留白，不缩文字；表单内部滚动，固定操作随IME inset上移，导航不被键盘遮住 |
| 导航轨剩余高度不足容纳六个48dp目标及间距 | 低频电子秤/设置移至顶栏“工具”菜单，四主目的地顺序不变；不能裁切或让工具消失 |

实时图先测量标签和轴，以四轴布局的绘图区是否达到320dp作为切换判据，不强行把最窄窗口撑宽。已有窄窗回退采用两行图例、四量纲刻度和单图，配方移至图下；不再单独验收平板竖屏。若窄窗/大字号下四列刻度会把绘图区压到该目标以下，改为**同图聚焦模式**：绘图区使用窗口剩余宽度；所有有效系列仍可显示且各自独立投影；只把选中指标的完整物理轴放在绘图区旁，其他指标的单位及min–max在各自图例项始终可见，非选中线降低强调但不靠透明到不可读；切换选中项不改采样。图旁明确“各项使用独立量程”，不把这些线伪装成共用同一物理纵轴。此模式必须在实施中用真实控件检查量程文字，不照搬横屏四轴图缩小。

若高度很短，缩去重复读数/配方展开而不是停止和安全消息。详情进入独立面板而非挤占全部绘图；主任务框架和停止不随图表局部探索滚走。全系统最大字号时也不能靠字号截断通过几何测试；用已有上下文的局部面板保留完整操作和内容。

## 10. 组件和数据边界

继续使用现有原生Android View与Kotlin，不为这轮视觉改版迁入Compose或WebView，也不改蓝牙服务所有权。

| 边界 | 责任 | 不承担的责任 |
|---|---|---|
| 语义主题/控件 | 字号、颜色、间距、主/次/危险/禁用样式、无障碍名称 | 判断设备是否可控 |
| 自适应页面壳 | 导航、主区/辅区/局部编辑、Insets、稳定任务上下文 | 建BLE连接、启动萃取或库存写入 |
| 图表投影/渲染 | 从现有采样/来源生成有单位的系列、量程、缺口、探索信息 | 改历史数据、猜杯重、改变自动停水 |
| 页面展示状态 | 读取已有状态，产生可见文案/值/允许动作 | 新建与控制层竞争的安全状态机 |
| 原业务入口 | 原门禁、用户确认、单次派发、存储与幂等 | 根据图片或显示偏好改变协议 |

先隔离通用壳、控件和图表，再按任务迁移页面，避免把所有逻辑堆进一个新大Activity。组件接收明确展示数据及原事件回调；显示刷新不得触发回调。新导航的生命周期变化不能改变现有前后台观察和控制队列行为。

## 11. 验证与完成定义

改版完成需要下列证据，不以生成图、代码静态存在、构建成功或老CI替代。

1. 21页清单逐项核对：原字段、合法入口、排序、导入/分享、三日期、四阶段、复盘、库存/旧版来源全部保留。
2. 中文用户任务可走通：曲线选择→准备→启动确认；运行随时找到停止；结束复盘；新增库存→本杯选豆/确认耗用→查看流水；复制/分享→导入预览/冲突处理。禁用原因可理解。
3. 视觉人工审查：3秒能找当前状态/时间/主要数量/下一步/停止；不是所有按钮同色同大；图表为主；没有无语义色块或说明墙。必须查看实际新版渲染，不只看边界坐标。
4. 图表用确定采样验证单位换算、同一时刻、端点、独立量程、超范围、负值、缺失/恢复、不同来源/旧版、温度来源；未来不补造，按实际压力阶段保留断点。截图与数值断言互补，不仅检查画布非零。
5. 状态回归：未就绪、启动中、停止中、未知离线/就绪显式恢复、断秤、机器遥测过期、手动模式；不会自动重发、清未知记录、绕过门禁或重复扣豆。
6. 自适应：用户平板等效横竖窗口、紧凑窗口、至少fontScale1.0和1.3及系统最大字号、浅/深色、中文键盘；根无整页滚动，局部列表/编辑可滚；操作及安全提示不遮挡。测量与人工读图都通过才算布局可用。
7. 恢复：旋转、后台/前台、列表离返、输入/光标、选择器与文件返回；相同业务事件仍为一次，原生命周期/升级和协议回归不放松。
8. 相关自动化及四项必需CI运行到精确新源码；已知其他语言缺陷必须如实说明，不能标“全绿”。其他语言的精修后排，不能因此破坏功能入口。
9. 真实平板只在用户可用且授权的会话覆盖安装Mock，保留包名/签名/版本与数据；本轮不强迫重新接设备。模拟器与Mock验证不是咖啡机/秤实机控制验收，硬件结果单列，不作假。
