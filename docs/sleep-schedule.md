# 每周睡眠计划写入

旧版 `sleep.vue` 保存时调用 `setSleepArrTime(1)`，500 ms 后调用 `setSleepArrTime(0)`。页面没有调用旧代码中另存的 `setSleepTime` 单日函数。原生版因此按两包整周写入，不把单日函数当作实际使用路径。

计划按周日到周六排列。第一包 `09 10` 后接周日到周三各4字节，第二包 `09 0C` 后接周四到周六各4字节；每天为睡眠时、睡眠分、唤醒时、唤醒分，睡眠时最高位表示当天启用，末尾补 `00`。帧长分别为19和15字节。`scripts/generate_sleep_schedule_oracle.py` 只执行旧版的编码函数，生成三组差异化计划供逐字节验证。

机器回报为 `0x83 0x40` 与 `0x83 0x80` 两段。前段包含周日到周三时间及周日到周六的启用位，后段包含周四到周六时间。原生页面只有两段完整回报后才允许编辑；一次修改一天，另外六天保持机器回报值。服务层发送前再次核对完整基线和新鲜、已唤醒的待机遥测。会话层只对已验证固件开放控制，先写19字节，首包传输成功500 ms后才写15字节。两包写入成功仍只是传输证据；之后两段新的机器回报与目标整周完全一致才算确认。

第一包可能写入而第二包失败，机器端是否原子应用未知。此时结果为未知，不自动回滚或重发第二包；用户需核对机器上的计划，再次编辑前必须重新收到两段完整回报。当前尚无实机写入及回报时序证据，不能把离线逐字节匹配当作硬件验收。
