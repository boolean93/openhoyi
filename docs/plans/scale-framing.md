# Acaia / TIMEMORE 通知边界安全修复

- 需求与范围：丢失尾片后收到新帧时，不制造校验错误或接受跨帧假重量；保留合法拆包、真实坏帧失效及单位/去皮门禁。仅本工作树，不涉及 DiFluid 修复。
- 来源/目标：`origin/develop` `bc078c89`；工作分支 `fix/scale-framing`，后续 PR 目标 `develop`。
- 分工：实现者修改协议和会话回归；独立 Astra 只读复核算法及差异。
- 步骤：比较旧片拼接候选与新通知起点完整候选；新候选未完整时有界等待，不提前发布拼接重量。只有旧候选校验失败、新候选完整有效才安静重同步。两种解释均有效或旧候选未完整时保守报告边界歧义，清单位信任，等待新的克单位确认。
- 验证：运行 `:protocol-core:check`、`:device-session:test`，覆盖全部正常切分点、分片重启、保留 CRC 零值、真实损坏、单位与去皮门禁；记录实际结果，不声称硬件验证。
- 协议风险：不以 header 独自判边界；合法 payload 可含 header。歧义丢弃本次输入，不重放、不自动写入或重发去皮。未知完整候选保守歧义失效；真实坏帧仍按校验失败处理。CRC 零值兼容不删除：固定厂商协议 e31dce5087494ea3d572a89e689e48dc014eee2c 只写 `CRC field reserved` 并定义 CRC16IBM，并未逐字保证 0000；零值接受是既有兼容解释，非实机证据。
- 恢复边界：仅保护已有 pending 且后续真实 notify 起点匹配 header 或其首字节的重启候选；不扫描单个通知内部所有潜在头，不宣称恢复任意流内部损坏或完美识别校验碰撞。
- 推送/PR：本轮不推送、不建 PR、不合并；后续需普通推送及仓库必需检查。
- 发布/签名/升级：不发版、不安装、不接触设备；不改包名、签名、版本、存储。
- 回退：只回退本任务代码，不删除历史或未确认去皮记录。
- 未完成：实机及固件兼容验证；软件测试不能替代硬件验收。
