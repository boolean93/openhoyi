# 预热待确认恢复入口

遵循 [Git 工作流](../git-workflow.md) 和 [规划模板](task-template.md)。

- 需求与范围：持久化的预热未确认记录不再只显示「暂不可用」。在任务栏和首页打开同一个原地核对框，显示何时可确认。正常预热进度、断线、机器告警和正在萃取仍按原优先级显示。只解除旧预热对独立秤自动连接和本地重量采集的误锁。
- 基线：`origin/develop` `e0cea92d`；工作分支 `fix/brew-wait-recovery-entry`，PR 目标 `develop`。
- 实现：让待机遥测序号独立于设置帧更新；确认重新核对同一条记录、同一咖啡机、当前连接、更新的新鲜清醒待机、阻断告警和事务状态，仍须用户明确确认。
- 推送与合并：本地核对后普通推送工作分支，通过 `scripts/create-pr` 创建 PR，独立复核体验及门禁并等待四项必需 CI 后合入。
- 验证：状态优先级单测、无设置回读的模拟 Service 恢复路径；运行本地 PR 检查和远端 CI，无真实设备操作。
- 协议与设备风险：不改报文、机器写入门禁和重试；不将待机帧当成取消回读、不自动消除未知记录。确认只清除本地提示、不发指令。
- 发布：不打标签，不发版、不签名、不安装。回退用代码 revert，保留机器安全记录，不卸载或清理数据。
