# BLE V2：已认证但设置回读过期

来源 `e0004018`；隔离本地分支 `fix/ble-v2-manual-settings-sync-local`。本轮不推送、不建 PR、不打包安装。旧版、签名、正式包和恢复记录边界不变。

- 不加手动同步入口或弹窗。前台 READY 设置过期且同源原生 Idle 安全，先让正常 0x83 回报 350ms；没收到才为当前基线自动发一次 0x01（会校时）。这不是定时轮询：同一来源及基线超时、前后台、刷新 UI 都不自动再发。不知道锅炉当前开关就不猜，也不保存待执行锅炉指令。
- 已提交的 V2 锅炉操作也先被动等 350ms，仍待回报才尝试最多一次同源 0x01；周表和锅炉重叠时，必须先结算周表所有权，且仍在锅炉原有 6s 窗口内才可同步。原命令未发送、用户停止、连接或原所有权改变、正在萃取/预热或有报警时不可补发。同步不是原命令重发，不自动重连，不凭 ATT 回执确认设置。
- 自动同步未确认时，短冷却后同一个开关可再发一条有界读取，不改开关方向。手势按下已处于读取模式，即使抬手前回报了真实配置，也不会升级成锅炉操作。只有后续独立明确的一次点击才能使用新基线写入绝对开关。未知写入保留持久围栏；普通锅炉的同位置读回须来自原设备同代。周表并行写入若最终未知，保留原来的逐项核对路径，不因再次点开关清除记录。若仍冲突或无法成证，不以清记录或猜测放行。
- 0x83 同时携带多个设置，不是独立的每字段回执。新基线依赖当前认证来源、原生捕获时间、顺序和既有时间阈值；取证不遮盖实时温度、压力或紧急 STOP。设置回报本身缺失且 ATT 已回执不等于断线；ATT 无回调仍沿用原串行传输的安全超时。
- 同包 Mock 界面验收准备（未运行）：`-PhoyiBleSameIdQa=true -PhoyiBleV2Delivery=true`，设置→维护与诊断→「模拟：设置回读过期与同步」。共用产品状态渲染，不是正式的导航验证。用模拟时钟走 READY＋过期、350ms 自动一次 0x01、ACK 后未恢复、当前 83 恢复／超时；超时后模拟冷却，再在同位置开关点一次，核对只有第二条 0x01，始终不发锅炉命令。关闭弹窗销毁隔离服务和随机目录。实机、真实进程重建和旧 APK 回退未验收。
