# 累计杯数重置

旧版 `rstCups` 固定发送 `0A01A5A500`，长度 5 字节。`scripts/generate_cup_reset_oracle.py` 只提取旧版编码函数，生成 `protocol-core/src/test/resources/cup_reset_wire.tsv` 作为字节对照。现有采集记录没有真实执行杯数重置的样本，因此只确认旧版代码中的请求帧，不能声称已确认机器执行时序。

旧版页面用 App 本地的设置密码作确认，默认值可在旧版内修改。这不是咖啡机蓝牙认证密码，原生版也没有迁移旧版本地密码。原生版改用输入当前杯数、再次确认的交互。服务层还要求已验证固件、咖啡机就绪、没有萃取或其它待确认控制、最新唤醒待机遥测，并要求 `Settings` 与 `IdleTelemetry` 回报的杯数都等于用户输入值且大于零。

BLE 写入成功只表示命令送达传输层。写入之后，新收到的 `Settings` 或 `IdleTelemetry` 报文杯数为零才显示“机器已回报 0 杯”。断线或 12 秒内没有归零回报显示“结果未知”，不自动重发；写入失败显示失败。状态未知时应先看机器与最新回报，再决定是否重新操作。此功能尚未在 Alpha 上实机执行。
