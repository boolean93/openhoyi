# Native 重构：蓝牙协议基线

这组文档把拆包应用中的蓝牙行为整理成与 uni-app、JavaScript 和页面状态无关的协议基线，供新的 Android Native 工程直接实现。

## 结论

- 咖啡机和电子秤是两条独立 BLE 链路，应各自维护 `BluetoothGatt`、连接状态机和串行操作队列。
- 咖啡机使用私有 GATT。通知首字节决定消息类型，主要为 `0x40`、`0x80`、`0x83` 和 OTA 的 `0xA0`～`0xA5`。
- 电子秤不是单一协议。旧应用按设备名选择 Acaia、Felicita、DiFluid/Microbalance 和 BOOKOO 四类适配器。
- 旧应用假设一次 BLE notification 就是一帧，没有通用帧头、帧长或统一校验。这一点必须在真机抓包中验证，Native 实现不能静默拼错数据。
- 已能从代码确定 GATT UUID、绝大多数命令字节、遥测字段和初始化时序。DiFluid 的部分重量解析、咖啡机若干状态位、OTA 细节仍需抓包确认。

## 可信度标记

- **C1 已确认**：拆包代码明确构造或解析该字节。
- **C2 强推断**：代码行为清晰，但没有设备侧协议或抓包佐证。
- **C3 待验证**：旧代码使用启发式或同一字节有多种解释，必须抓包。

这些文档描述“旧应用实际做了什么”，不把旧实现中的缺陷当作新协议要求。发现旧代码构造长度与实际十六进制长度不一致时，会单独标出。

## 证据入口

所有结论都来自：

- 咖啡机 BLE 模块：`app-service.js` 的模块 `8625`，约 40535～42556 行。
- 电子秤 BLE 模块：模块 `c904`，约 61642～63586 行。
- 电子秤设备识别：模块 `e7cf`，约 71095 行。
- 首页及连接页上行解析：约 19590、22450、78220 行。
- 实时萃取解析：约 70590 行。
- OTA 页面解析：约 26390 行。

行号对应当前恢复版 `app/assets/apps/__UNI__7D80DAB/www/app-service.js`。
