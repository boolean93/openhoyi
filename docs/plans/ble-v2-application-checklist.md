# BLE 应用层 V2：按逐项对照验收

- 本地分支 `feat/ble-v2-service-local` 从已复核阶段七 `78ffba9a` 起步；最终目标 `develop`。当前仅本地，无推送、PR、APK 安装、设备或固件操作。
- 下表来源为已交付的《OpenHOYI 蓝牙协议逐条对照》21 个现有 App 意图；其证据类别是最低验收要求，不因链路回执、无报错、CI 全绿而降低。
- 阶段 8A 只接线 opt-in `-PhoyiBleV2Delivery=true` 的运输层投影：保留原指令编码、传输、准入、回读、恢复和显示；状态只读不准入。本阶段没有完整 V2、实际设备或 Android Mock 验收结论。Debug 选项不改变 applicationId、签名或安装边界，切回默认无数据迁移。
- 投影是当前 GATT 代次、每类最近一条送达运输队列的快照；它不是完整事务日志，也不覆盖入队前拒绝，不被 UI 当作操作成功。心跳及第三方秤不在投影内；初次认证、握手补充同步和 READY 期同步分别归类。测试见 `CoffeeDeliveryTest` 与 `GattQueueCleanupTest`，属于假驱动 JVM 层，不代替逐项场景和可安装 Mock 的 UI/生命周期证据。
- 验收要同时保留：前台实时数据不因确认等待阻断；STOP 不依赖持久化写锁、排队优先，不抢已交给传输的一条；不自动重发效果未知的实际控制；重连只能读取确认证据，保留旧代/他机拒绝、重启未知记录、旧读取器围栏、未绑定设备和数据安全。投影默认关闭；默认行为仅收紧 STOP 同代同步回调重入的优先权，不影响替换连接。

**排除范围**：原表另列 13 项官方／旧接口（含 OTA）；保持原产品能力边界，不因架构改动开放或变更这些接口、OTA 和第三方秤协议。不自动执行未授权命令，不升级/回退机器固件，也不冒用新版实验包替代最终真机验收。

**8B 萃取开始的证据边界**：有效的新阀门帧可以早于 GATT 回调。排队、旧连接、错 endpoint、预热、重复帧或相对于发送时间已运行很久的杯不确认。由于线包没有事务 ID，此处文案只说观察到机器萃取，不宣称证明指令因果或槽位；无法可靠归属时显示未确认，不重发。安全自动停、手动 STOP、计时及历史原路径不从这个页面投影获得权限。

**8C 设置回读**：0x03/04/05/06/0E/0F/10/14/15 的实际普通或后台温控服务写入得到与具体变更绑定的 cut。只有同一已认证连接中切点后的新鲜普通设置帧可推进原有确认；字段不匹配不能当成功，并保留既有未知／人工恢复。0x14 的后续伴随字段不能用先于原写回调但处理较晚的通知解锁，且换成别的温度指令也不能抹掉该保护。重连的新鲜设置只可建立明确下一次请求的基线，不替旧请求确认。普通设置断线未知后，只有满足同机／新源证据且人工确认清除原恢复记录，才释放原内存门禁，不补发。0x0C/0D 需要条件重连的显式重新绑定，仍沿用原路径，不能把它记成新收据已迁移。0x08 与 0x11 零目标缺少可验证专属证明，不升级为成功。真实服务接线测试用隔离 Fake GATT，而非普通视觉 Mock；Android 测试仅编译不代表执行。
