# 蓝牙 v2 用户操作与异常恢复

基线为已审查的 v2 提交 `1fd33893`，本地工作分支为 `fix/ble-v2-user-recovery`。原分支的 origin 指向本机仓库。此次仅修复、回归和复核，后续集成按仓库 PR 流程进入 develop。

1. 主页刷新只读取状态。触摸、键盘和无障碍操作均绑定到用户实际看到的开关动作。启动进度和历史使用本次萃取的机器回报。
2. 会话和服务沿用通知接收时间。检查延迟空闲、过期称重、认证前积压数据和传输损坏，保留停止通道。
3. 回放温控与周计划并发、半表恢复、清理存储失败。按实际缺少的回报提示，保留未知写入记录。手动回查只读设置。
4. 用已有的设置同步与启动竞争场景验证准备豆量、萃取记录、同步写入与启动写入的次序。

验证采用仓库协议回放、会话 JVM 测试、移动端聚焦单测和 M2105K81AC 平板的 Mock 界面。平板上的验收 Mock 与真实 BLE Debug 共用 `io.openhoyi.mobile.mock`。用户已授权在这个包位以原签名和 versionCode 170 依次覆盖，验收完成后装回同源码 BLE Debug。正式包位的开发渠道版 182 保留。此次没有发版授权。回退可使用覆盖前留存的同签名 170 APK；设备和豆量日志由原有恢复流程处理。

## 回归结果

- 协议回放处理 32,856 条采集通知。904 项会话 JVM 测试、103 项会话检查和 68 项移动端聚焦单测通过。额外验证了损坏的 Idle 与设置包、认证前积压的旧包、去皮回调前采集的零点与超时后的同源设置回报。
- 平板隔离驱动的 52 项命令与拒绝场景逐项通过。18g 已备豆量在设置同步写入未结束时未被认领；传输完成后再次点击启动，归属本杯且库存只扣一次。温控等待和结果未知两种状态都可独占执行周计划，两段缺失提示与重建恢复均有覆盖。[逐项记录](../evidence/ble-v2-user-recovery/tablet-matrix.txt)
- 平板实测原生按键和无障碍动作。刷新手势跨越新回报而完成时，模拟锅炉写入为零；重新明确点击开关后只有一条锅炉写入。[刷新界面](../evidence/ble-v2-user-recovery/refresh-after-toggle.png)
- 启动回执和第一条有效萃取帧都保持等待，停止按钮可用；同次萃取计时向前后显示已观察到机器萃取。历史沿用相同证据。[等待界面](../evidence/ble-v2-user-recovery/shot-waiting.png) · [确认界面](../evidence/ble-v2-user-recovery/shot-confirmed.png)

界面和持久化回归使用平板上的隔离服务、模拟 GATT 和独立库存。断电、系统 TalkBack 手势和真实咖啡机或秤的操作未做实测。

## 常规 OpenHOYI Debug 182 试用回归

试用反馈基于同分支 `a2c03113` 的常规 Debug 主包 182。验收覆盖冲泡与蒸汽开关的开启和关闭：正常写入、等待读回以及确认后，开关下方都不增加文字；真正失败和需要手动处理的入口继续可见。同类排查还覆盖设置摘要、周计划、目标温度、杯数、拨杆、电子秤去皮，以及萃取页、导航和通知。正式交互沿用服务的写入门禁、停止入口和原设备回报；单独的 QA 页面可显示传输细节。

官方 dev-182 的标签指向 `3ced959f`；从 v2 的 develop 分叉点 `2496d5dc` 到该标签有三个提交。按用户要求合入机身手动萃取页（#177）、结果卡与单杯 AI 评价（#178）、设置设备行秤电量（#179）。平板常规 Debug 主包沿用同包、同签名、同 versionCode 的覆盖流程。


`fec74b86` 将正常锅炉读回加到了开关下方，也将后台设置同步接回生产摘要。当前合并提交 `c50fa2fc` 包含官方 `dev-182` 及 v2 修复。设置开关依据机器回报显示，周计划完整确认后显示「已保存」，杯数归零只在计数确认后显示。首页、萃取页、设备栏和通知都区分本次操作与需要核对的异常。正常 App 萃取及机身手动出液只静默自己这一杯的恢复记录；旧记录、断线、未知结果继续提示。

常规 Debug 开启 `BLE_V2_DELIVERY` 和 `BLE_V2_SPLIT_ADMISSION`。`protocol-core:verify` 回放 32,856 条采集通知；103 项会话检查、32 项设备会话单测、68 项移动端单测通过。覆盖官方手动萃取路由、单杯评价归属、秤电量，以及本轮修改的开始、停止、设置与恢复提示。

平板 M2105K81AC 的原生开关检查通过，覆盖明暗模式、键盘及无障碍。复跑过期回读用例，旧手势与延迟的无障碍读取都没有写锅炉，明确再次点开关才发出一条模拟命令。复跑原有 52 项命令和恢复矩阵，全部通过。模拟启动回执和首帧后仍为「启动中」且可停止，有效计时向前后转为「萃取中」，点停止后显示「正在停止」。四个阶段均检查了异常提示。离线结果卡显示「AI 评价」入口。

## 合入 develop

平板试用后，用户确认常规 OpenHOYI 默认使用本次试用的 v2 配置。Debug 和 Release 共用 `BLE_V2_DELIVERY=true`、`BLE_V2_SPLIT_ADMISSION=true`，develop 自动构建的主包也沿用此配置。Mock 与更新测试包使用模拟驱动。开发时显式传 `-PhoyiBleV2Delivery=false` 可同时关闭两项；旧读取器遇到 v2 待核对记录仍保持保护。PR 按仓库流程进入 develop，通过必需 CI 后合并。
