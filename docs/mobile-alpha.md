# OpenHOYI Alpha 第一段功能

包名 `io.openhoyi.mobile`；独立于 `io.openhoyi.lab` 诊断包和旧 HOYI。没有 UniApp、JS 或 WebView。`HomeActivity` 只负责权限、扫描选择和展示，`MobileService` 持有 `NativeDeviceHub` 及双 BLE 连接，曲线页从 `CurveLibrary` 浏览旧版工厂元数据和已采集曲线。设备会话和编解码复用 `device-session` / `protocol-core`；两款应用通过独立的私有目录使用共享 `trace-core` 实现记录，不混用日志文件。

## 已实现

- 原生首页：启动/停止前台设备服务、扫描 HOYI/BOOKOO、输入六位咖啡机密码并连接、分别断开设备；已成功连接过的 BOOKOO 地址保存在本包；首页进入前台且权限、蓝牙可用时，即使咖啡机未连接也会自动启动服务，在前台的10分钟窗口内轮询重连。手动断开会终止本轮重试；仅因自动重连启动且始终没有连接时，后台或窗口期结束后停止服务。可独立对已就绪的 BOOKOO 去皮。写入成功后还要等待新鲜的近零读数才显示“已归零”，超时显示“结果未知”；萃取期间不开放手动去皮。首页可确认后发送一次性立即睡眠命令；只有后续待机遥测回报睡眠状态1才显示确认。App没有唤醒命令，须用机器拨杆唤醒；机器入睡或睡眠状态未知时不允许发起萃取。新鲜待机帧含 C1–C14 故障或未知 bit15 时也阻止启动；C16“尾水允许中”只提示，不作为硬阻断。
- 实时状态：咖啡机温度/压力、固件号及秤重量；超过1.5秒的数据不标为实时。首页和萃取页显示 `0x40` 待机遥测中的告警位；按旧版顺序将 bit0–14 映射为 C1–C14、C16，bit15 显示为未知告警位。萃取中若没有新的待机遥测，显示上次告警并注明已过期，不把旧状态当成当前状态。当前只读显示，不发送旧版的“忽略告警”操作。
- 机器设置页：展示设备返回的固件、设定温度、加热、待机、杯数和两段每周睡眠计划。可修改萃取设定温度（75–105 °C）、冲泡温差补偿（0–5 °C）、蒸汽设定温度（110–145 °C）、两路加热、照明、自动待机时间、待机温度（0–100 °C）、水箱/外接水管供水来源、咖啡馆/工作室运行模式及每周睡眠计划总开关。旧版待机写入用 `0–4` 档位，机器回读用 `0/15/30/60/120` 分钟；修改时间时保留机器回报的待机温度；修改温度时保留机器回报的时间档位。首页显示并可切换手动、自动压力、自动流量三种拨杆模式；这些设置的593条允许参数报文均与旧版编码函数逐字节对照。写入前要求已验证固件、当前连接设置帧、新鲜且明确唤醒的待机遥测，并且没有进行中的萃取；写入后必须收到新的匹配 `0x83` 设置帧才显示已确认，否则显示失败或未知。拨杆模式使用 `flags` 的 `0x80`/`0x40` 位，`0x40` 单独置位显示未知组合。运行模式位 `0x04` 与拨杆模式独立；工作室模式下要求曲线目标温度与当前补偿后冲泡温度相差不超过1°C。每日启用位按旧版位图显示；开启总开关要求两段计划及时间字段完整且有效。供水来源使用旧版 `setWaterInMode`（0x10），与自动排水的 `setWaterMode`（0x12）不同；切换前需核对机器实际进水方式。每日时间编辑见下条；累计杯数重置见[独立说明](cup-count-reset.md)。
- 曲线库：三条来自采集记录的完整参数，以及100条旧版内置工厂曲线。可按分类与名称搜索、查看详情、设为当前曲线；选择只保存 ID。没有通过启动报文校验的曲线只能浏览，不能设为当前曲线。100条工厂曲线的有秤/无秤共200条启动报文已与旧版编码函数逐字节对照；校验失败则只能浏览。三条采集曲线仍用临时编号，不声称对应旧版曲线名称。数据来源、转换和校验见[工厂曲线导入](factory-curves.md)。
- 首页五个快捷槽位：默认使用旧版前五条工厂曲线，可在曲线库将任意工厂曲线放入槽位。五槽位的1000条有秤/无秤启动帧已与旧版 `startChart` 编码函数逐字节对照；点击先进入萃取确认页。启动和停止携带相同槽位，历史记录保存槽位。槽位映射只存在本包，不修改旧版数据。
- 每周睡眠计划：完整收到 `0x83 0x40` 与 `0x83 0x80` 两段后，可编辑周日到周六各日的启用状态、睡眠和唤醒时间。旧版实际保存路径写两包整周计划（19/15字节，间隔500 ms）；原生版一次只允许改一天，其余六天按本次完整回读保留。发送前核对整周基线、固件与唤醒待机状态；两包都写成功后，还需收到两段新的、与目标整周一致的回报才显示确认。部分写入、断线或回报缺失显示未知，须核对机器计划，重新收到两段完整回报后才可再编辑；没有自动重发或回滚。
- 记忆秤：成功 Ready 后在本包保存秤地址；前台10分钟窗口由 `NativeDeviceHub` 负责自动连接。扫描结果中重复选择同一台已连接或正在连接的秤不会断开重连；选择另一台仍会切换。
- 页面可见性由每个 Activity 的独立 token 汇总；从首页切到萃取页或设置页不应因旧页面停止而立即关闭前台重连窗口。最后一个页面离开后等待500毫秒，避开页面切换间隙。
- 操作与传输记录：共享 `TraceStore` 有界异步写入，认证帧在传输边界脱敏；首页可通过系统文件选择器导出ZIP。Alpha与Lab各有自己的日志session。
- 萃取页：选定已验证报文的曲线后展示连接、重量、温度、压力和萃取状态。确认框展示有秤/无秤模式、最大水量和目标重量；确认后才调用共享 `ExtractionController`。服务层重复校验曲线、确认时的秤模式、固件就绪、咖啡机新鲜待机帧及秤数据时效，并记录尝试/结果/传输。萃取页和首页均有单击停止入口；停止请求处理中按钮禁用，结果未确认时阻止主动断链或停止服务，断线结果未知时可重连后显式重试停止，不自动重放启动。启动、萃取或停止期间连接中断时，首页显示醒目的人工检查提示，前台服务通知改为安全警示并尝试发送高优先级提醒；结果未知的提醒持续到明确观察终态。进入萃取页时会申请一次Android通知权限；若未授权，启动确认和页面会明确提示后台断链提醒可能不可见。通知权限关闭时，高优先级提醒不保证出现在通知栏，前台页面提示仍可见。
- 工作室温度准备：若补偿后冲泡温度与曲线目标相差超过1°C，用户可显式发送旧版 `setBrewWait(目标温度)`；写入后还需新鲜温度遥测才显示就绪，之后必须再次确认才能发启动命令。可发送 `setBrewWait(0)` 取消；取消写入没有独立机器回读，不声称机器已确认取消。预热10分钟未完成会尝试自动取消；预热未处理期间阻止改设置、立即睡眠、断链、切换咖啡机和停服务；这些动作会先尝试取消。32条允许目标/取消报文与旧版编码器逐字节对照。尚未实机验证预热、取消和启动时序。
- 原生萃取图：服务层从机器 `0x80` 通知记录时间、压力、水流、累计水量、温度，并在秤读数足够新鲜时附上重量；页面用 Android Canvas 实时绘制压力、水流、重量。每杯最多保留2000点，长时萃取逐级降采样，保留最新点。
- 萃取历史：仅记录 Alpha 发起的请求，保存曲线ID、开始时间、观察到的终态、停止原因及可用时的秤读数。首个采样点以及之后约每5秒异步暂存一次；明确观察结束后再写最终采样点，历史详情可离线绘图。异常断线或进程中断时可保留最近一次已落盘的部分曲线，但最后几秒与尚未完成的异步写入仍可能丢失。结果未知会保留为未知；进程中断时的未完成记录在下一次启动标为未知，不假定成功。历史页可通过系统文件选择器导出 ZIP，包含状态/停止原因 CSV 与每杯可用的采样 TSV；读取失败的单杯会在 CSV 中标为 unavailable，不影响其它杯。导出时结果未知仍按 UNKNOWN 记录，曲线可能不完整。历史最多保留30天/500条。旧App历史不会自动迁入。

## 仍未开放

产品页尚有其它低频设备设置未接入，也不开放校准或 OTA。底层控制仍受已知固件限制；工厂曲线启动需要两套旧版帧对照通过。旧版用户自定义曲线尚未导入。萃取页已经接通启动/停止代码，但尚未在Alpha上完成真实启动、去皮确认、按重量停止和异常恢复验证；独立去皮及设置写入也未实机验收。不能视为与旧App硬件等效。App进程被系统杀死时不能保证停液。

## 验证

工厂曲线100条在临时槽位有秤/无秤共200帧、五个快捷槽位共1000帧，均由只提取旧版编码函数的离线脚本生成；机器设置593帧；预热和取消的32帧另由旧版设置编码函数生成。资源可重复生成且字节一致。告警位使用合成 `0x40` 帧及页面状态单测核验；现有采集记录没有非零告警帧，告警文案和时序尚未实机验收。协议检查36,796项、会话检查36项、Alpha单测58项通过，debug构建成功；Lint结果见[覆盖矩阵](coverage.md)。当前用户要求暂不安装，新增页面尚未实机检查。
